## Summary

When host UID ≠ 1000 (macOS Docker Desktop, some Linux configs), `oh` / `claude` / `codex` / `pi` inside the sandbox hit EACCES on first run:

```
sandbox@<container>:~/harness$ oh
Error: EACCES: permission denied, mkdir '/home/sandbox/.pi/agent/sessions/--home-sandbox-harness--'
    at mkdirSync (node:fs:1370:26)
```

Bind-mounted `~/.claude` / `~/.codex` / `~/.pi` files keep their host UID inside the container. Mode-0600 credential files can't be read across UIDs, and mode-0700 dirs (`~/.pi/agent/sessions/`) reject writes from non-owner UIDs. `entrypoint.sh:28` deliberately skips `chown` when `PI_HOST_BIND_MOUNT=1` (host-side perms must not be rewritten).

#196 detected the mismatch but only printed a multi-line warning telling the user to manually edit `.openharness/config.json` — easy to miss in a curl-pipe firehose.

This PR auto-remediates: when UID ≠ 1000, `jq` filters `claude-host.yml`, `codex-host.yml`, `pi-host.yml` out of `composeOverrides`. The base named volumes (`claude-auth`, `codex-auth`, `pi-auth`) take over; `entrypoint.sh` chowns them to UID 1000 on first boot. Idempotent — `cmp -s` short-circuits the rewrite on subsequent runs. Falls back to the original warning when `jq` is unavailable.
