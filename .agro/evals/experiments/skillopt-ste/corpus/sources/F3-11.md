## Summary

`render-log-entry.sh` — the Step 5 helper every `/prompt-miner` exit path is required to call — resolves its write root with:

```bash
# .oh/skills/prompt-miner/scripts/render-log-entry.sh:47
ROOT="${AUTOPILOT_LOG_ROOT:-$(git rev-parse --show-toplevel)}"
```

Under `worktree: true` (which `.oh/crons/prompt-miner.md:8` declares), `git rev-parse --show-toplevel` returns the **ephemeral cron worktree**, not the shared root checkout. The daily-log entry is written into `.oh/worktrees/cron/<session>/.oh/memory/<day>/log.md` and disappears when the runtime reaps the worktree.

## Why the mitigation does not cover it

The cron body already solves this — but only for its own Step 4 liveness line, and only as a local shell variable that is never exported:

```bash
# .oh/crons/prompt-miner.md:102
ROOT="${AUTOPILOT_LOG_ROOT:-$(git -C "${CRON_WORKTREE:-.}" worktree list --porcelain 2>/dev/null | awk 'NR==1{sub(/^worktree /,"");print;exit}')}"
ROOT="${ROOT:-$(git rev-parse --show-toplevel)}"
```

`.oh/crons/README.md:120` documents this `CRON_WORKTREE` → shared-root mapping as the standing autopilot convention. The helper does not implement it — it only honors `AUTOPILOT_LOG_ROOT`, which nothing in the cron path exports. So Step 4's liveness line survives the reap and Step 5's daily-log entry does not.

## Evidence it fires in production

`.oh/crons/.cron.log`:

- **07-10** — "2 engine defects logged: symlink entrypoint no-op, **worktree log-loss**"
- **07-14** — same defect logged again
- **07-19** — "REPEAT BLOCKER (3rd day)… Also recurrence of 07-14 defect: **artifacts+log default into the reaped worktree; copied to shared root and forced `AUTOPILOT_LOG_ROOT` this run.**"

Three occurrences, recovered by hand each time. A workaround an agent must remember is not a fix.

## Fix

Mirror the documented convention in the helper itself, so no caller has to remember to export anything:

```bash
ROOT="${AUTOPILOT_LOG_ROOT:-$(git -C "${CRON_WORKTREE:-.}" worktree list --porcelain 2>/dev/null | awk 'NR==1{sub(/^worktree /,"");print;exit}')}"
ROOT="${ROOT:-$(git rev-parse --show-toplevel)}"
```

`git worktree list` prints the **main** worktree first, so `NR==1` is the shared root from inside any linked worktree.

## Acceptance criteria

- `render-log-entry.sh` resolves the shared root from inside a linked worktree with no environment variable set by the caller.
- A test or probe invokes the helper from inside a real `git worktree` and asserts the entry landed under the **main** worktree's memory dir.
- The precedence order `AUTOPILOT_LOG_ROOT` → `CRON_WORKTREE` mapping → current toplevel is preserved, so existing callers that do export the variable are unaffected.
- The duplicated resolution block in `.oh/crons/prompt-miner.md:102` is left working (it is correct today); consider pointing it at the helper's logic once the helper is authoritative.
