## Summary
Fix the release process so CHANGELOG promotion commits do not live only on `main` / `release/*`.

## Problem
The `/release` flow promotes `CHANGELOG.md` locally, then pushes the release branch and tag, but does not push the source branch (`development`) with the promotion commit. After the release branch is merged to `main`, `development` keeps stale entries under `[Unreleased]`, so later work re-carries already-released changelog entries.

## Scope
- Update release docs/skill to push the source branch after promoting CHANGELOG and before tagging.
- Document why this is required.
- Repair current CHANGELOG drift by preserving released sections from `main` while keeping new unreleased entries on `development`.
