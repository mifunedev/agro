## Description

Frame the orchestrator-via-VS-Code-attach as the canonical Open Harness workflow across the early docs surfaces. Add a Mermaid architecture diagram so the host/sandbox/orchestrator/surfaces split is visible at a glance, and fix a dark-mode inline-code contrast bug in the docs site that the work surfaced.

## Context

- `docs/quickstart.md` didn't surface the VS Code Dev Containers attach pattern, which is the most consistent and productive setup both locally and over Remote-SSH.
- `docs/intro.md` "How it works" described lifecycle but never named the **orchestrator** or its role, and had no visual aid.
- `docs/agents/overview.md` had a redundant "Running an agent in tmux" section that overlapped with the Pi+Slack / T3 Code / docs surfaces story.
- Dark-mode inline `code` pills in the docs site were nearly invisible against pure-black surfaces (background `rgba(255,255,255,0.06)`, border `0.1`).
