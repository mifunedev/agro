## RCA
Installed Pi package inspection found the failure originates in `@earendil-works/pi-ai@0.79.9` under `@earendil-works/pi-coding-agent@0.79.9`: the `openai-codex-responses` provider uses WebSocket cached continuation, sends `previous_response_id`, clears stale continuation on error, then rethrows. Pi's agent retry classifier does not include `previous_response_not_found`, so non-Slack loop/interactive turns were lost instead of retried. The existing bridge recovery extension is intentionally Slack-scoped and not auto-loaded for normal Pi sessions.
