## Problem

Too many places for project documentation with unclear boundaries. The old `next-postgres-shadcn` name persists everywhere (~60 locations). No unified search across docs + wiki. No quality gate for content. Tunnel routing serves only one subdomain.

## Outcome

Every component explicitly defined, documentation unified under one site (`oh-docs.ruska.dev`), all references modernized to `openharness`, tunnel subdomains configured.

## Changes (7 targeted fixes)

### 1. Create `/content-gate` skill
New quality gate for all published content (docs MDX + wiki MD). Checks frontmatter, conciseness (<2% filler), heading hierarchy, broken links, code block language tags, minimum length. Includes visual render verification via `/agent-browser`.

### 2. Fix search to index wiki + docs
`docs/app/api/search/route.ts` — currently only indexes `docsSource`. Merge both `docsSource` and `wikiSource` into the search index.

### 3. Add cross-link from docs → product app
`docs/lib/layout.shared.tsx` — add "App" nav link pointing to `https://oh.ruska.dev`.

### 4. Add next-app to pnpm workspace
`pnpm-workspace.yaml` — include `workspace/projects/next-app` so unified `pnpm dev` works.

### 5. Add unified dev script
Root `package.json` — `"dev": "pnpm --filter @openharness/docs dev & pnpm --filter next-app dev"`.

### 6. Rename `next-postgres-shadcn` → `openharness` everywhere
~60 file references across CI workflows, issue templates, skills, scripts, agent configs, and next-app. See replacement map in plan for exact old→new mappings.

### 7. Cloudflared tunnel — subdomain routing
Single tunnel, multi-ingress: `oh.ruska.dev → :3000` (product), `oh-docs.ruska.dev → :3001` (docs). Update `install/cloudflared-tunnel.sh` to accept multiple `hostname:port` pairs.

## System taxonomy

After completion, the system has three clear layers:

| Layer | URL | Purpose |
|-------|-----|---------|
| **Product** | `oh.ruska.dev` | Revenue-generating app, autonomously built by agents |
| **Knowledge** | `oh-docs.ruska.dev` | Unified docs + wiki, quality-gated, searchable |
| **Infrastructure** | (no public URL) | Harness that makes the above two possible |
