Closes #693.

## What was wrong

`.oh/skills/prompt-miner/scripts/render-log-entry.sh:47` resolved its write root with:

```bash
ROOT="${AUTOPILOT_LOG_ROOT:-$(git rev-parse --show-toplevel)}"
```

Under the cron's `worktree: true` (`.oh/crons/prompt-miner.md:8`), `--show-toplevel` returns the
**linked** worktree. Every Step 5 daily-log entry was written into
`.oh/worktrees/cron/<session>/.oh/memory/<day>/log.md` and destroyed when the runtime reaped it.

The file's own header comment documented this as a contract — *"the cron path **may** export
`AUTOPILOT_LOG_ROOT`"* — but nothing in the cron path does. `SKILL.md` Step 5 calls the helper with
no such export, so the default path was the broken one and the workaround was undocumented at the
call site.

## Evidence it fired in production

`.oh/crons/.cron.log`, three occurrences, hand-recovered each time:

| date | entry |
|---|---|
| 07-10 | "2 engine defects logged: symlink entrypoint no-op, **worktree log-loss**" |
| 07-14 | same defect, naming `render-log-entry.sh:47` |
| 07-19 | "**Also recurrence of 07-14 defect: artifacts+log default into the reaped worktree; copied to shared root and forced `AUTOPILOT_LOG_ROOT` this run.**" |

A workaround an agent has to remember is not a fix.

## The fix

Adopts the resolution already proven at `.oh/crons/prompt-miner.md:102` and documented as the
standing convention at `.oh/crons/README.md:120` — `git worktree list --porcelain` prints the
**main** worktree first, so `NR==1` is the shared root from inside any linked worktree.

Precedence is preserved (`AUTOPILOT_LOG_ROOT` → `CRON_WORKTREE` mapping → toplevel), so callers
that already export the variable are unaffected. The header comment that described the bug as
intended behavior is corrected.

## Why the probe builds a real worktree

`.oh/evals/probes/prompt-miner-log-root-worktree.sh` creates a real linked worktree via
`git worktree add --detach`, runs the helper inside it with **both** env vars unset, and asserts
the entry landed in the main worktree — then asserts `AUTOPILOT_LOG_ROOT` still wins.

A fixture-based test cannot catch this class of bug. The defect is entirely in how the helper reads
git's view of the current directory, so a harness invoking it from the main checkout resolves the
same path either way and stays green with the bug live. That is precisely how this survived three
production occurrences.

## Falsifiability

| mutation | probe result |
|---|---|
| M0 — fixed resolver | **exit 0**, PASS |
| M1 — revert to `ROOT="${AUTOPILOT_LOG_ROOT:-$(git rev-parse --show-toplevel)}"` | **exit 1**, naming the linked-worktree path it wrongly wrote to |

Full suite: **95 probes**, new probe PASS. The single `REGRESSION` (`next-dev-prod`) pre-exists on
`development` and is untouched by this change.

## Scope note

`.oh/skills/retro/scripts/render-log-entry.sh` is a **different** script — a pure stdout formatter
that never resolves a root or writes a file — so no shared-helper refactor is warranted. This fix
is one file, one resolver.

## Adversarial review found a regression in this PR — fixed

Two independent critics audited this branch. One found that the new resolver, under
`set -euo pipefail`, **aborts the script** when `CRON_WORKTREE` points at something that is not a
git repo: `git` exits non-zero, `pipefail` propagates it out of the command substitution even
though `awk` exits 0, and `-e` kills the script before the fallback line can run.

```
$ env -u AUTOPILOT_LOG_ROOT CRON_WORKTREE=/tmp/notarepo bash render-log-entry.sh --result DRY-RUN
ERROR: render-log-entry.sh failed at line 57
```

**That was worse than the bug being fixed.** Before this PR the script never consulted
`CRON_WORKTREE`, so a stray value was harmless; the fix made it the primary input and therefore
lethal. And "not a git repo" is exactly what a reaped cron worktree looks like — the scenario this
helper exists to survive.

Now adopts the complete idiom from `.oh/skills/autopilot/autopilot-caps.sh:109`, which had it
right all along: `|| true` inside the substitution plus the stricter `NR==1 && $1 == "worktree"`
guard, so a first line that is not a worktree record cannot be mistaken for a path. The duplicated
snippet at `.oh/crons/prompt-miner.md:102` is updated too, so the docs stop propagating the
unguarded form.

The probe now asserts degrade-don't-abort directly, and is falsifiable against it: dropping
`|| true` makes it exit 1 naming the condition.
