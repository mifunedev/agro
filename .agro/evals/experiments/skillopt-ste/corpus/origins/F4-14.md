## What & why

To run `oh init` you need the `oh` binary — but there was **no host-side way to get it**: the CLI is a private, unpublished npm package (`.oh/cli` is `"private": true`), and `install.sh` only ever builds `oh` **inside** the container (`/opt/oh`). The only documented host path was a manual build buried at `installation.md:196`.

This adds **`.oh/scripts/get-oh.sh`** — a `curl | bash` bootstrap (same shape as `install.sh`) that clones the harness into `~/.openharness`, builds `.oh/cli` → `dist/oh.js`, and symlinks `oh` onto PATH. Then: `cd <project> && oh init`.

**The clone is kept on purpose.** The built binary resolves its scaffold payload relative to itself (`dist/oh.js → ../../templates` = `.oh/templates`, per `.oh/cli/src/cli.ts:24-43`), so a clone-anchored `oh` runs `oh init`/`oh update` from the **local** payload — no per-command network fetch — and sidesteps the `#564` publish-to-bundle blocker entirely.
