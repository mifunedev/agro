## Summary

UX hotfix to `main` so post-install instructions actually tell users to source their shell rc — without it, the curl-piped install completes successfully but `oh`/`node`/`pnpm` look "command not found" until the user opens a new terminal.

### Problem

```
$ curl -fsSL https://oh.mifune.dev/install.sh | bash
... installation succeeds, prints "Installation complete!" ...

$ oh --help
oh: command not found
$ node -v
Command 'node' not found, but can be installed with:
sudo apt install nodejs
```

Curl-piped install runs in a child bash; child shells can't export PATH back into the parent. nvm + `pnpm setup` write the needed exports to `~/.bashrc` / `~/.zshrc`, but the user's *current* shell needs to source those rc files (or open a new terminal) before the new binaries are visible.

The previous next-steps mentioned this only as a tiny "Reminder:" footer at the end. Users would run `oh sandbox` immediately in the same shell, see "command not found", and assume the install broke.

### Fix

Restructure next-steps so the rc-source is **Step 1** (printed prominently) before `cd`, `oh sandbox`, `oh shell`, etc.:

```
Next steps
──────────────────────────────────────

  1. Load Node + pnpm + oh into THIS shell (required — without this,
     'oh' / 'node' / 'pnpm' will be 'command not found' here):
       source ~/.bashrc
     (Or open a new terminal — same effect.)

  2. Move into the repo:
       cd ~/.openharness

  3. Provision your sandbox:
       oh sandbox <name>
  ...
```

Detect user's `$SHELL` so the printed rc path matches:
- `bash` → `source ~/.bashrc`
- `zsh` → `source ~/.zshrc`
- `fish` → `source ~/.config/fish/config.fish` (with extra warning that nvm needs nvm.fish)

Closes #189
