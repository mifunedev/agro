## Problem

Agents in the sandbox hold the Docker socket, which is deliberate — they need it for lifecycle work. But a bare `docker inspect <container>` prints the full container JSON, and that JSON carries `Config.Env`: every environment variable the container was started with, secrets included. One inspect call puts the whole env block into the transcript and the prompt cache.

The blunt fix — `Bash(command=*docker inspect*)` in `permissions.deny` — was in place, but it also removes the only way to read health status, mounts, networks, labels, and restart state, which the boot smoke script and several docs already depend on. It is also a settings-only rule, so it is not the same enforcement surface as the `PreToolUse` guard.

## Wanted

Field-level denial instead of a full block: deny the shapes that can expose env, keep narrow field reads usable.

Deny:
- bare `docker inspect <container>` (full JSON)
- any template naming `env`, e.g. `--format '{{.Config.Env}}'`, `{{index .Config.Env 0}}`, service `ContainerSpec.Env`
- whole-object expansions: `{{.}}`, `{{json .}}`, `{{.Config}}`, `--format json`
- `| jq …` pipes over full JSON — the guard cannot verify the filter
- the `podman` / `nerdctl` equivalents

Allow:
- `--format '{{.State.Health.Status}}'`, `'{{.NetworkSettings.IPAddress}}'`, `'{{json .State.Health}}'`, `'{{range .Mounts}}{{.Source}}{{end}}'`, image-id reads
- `docker ps` / `compose` / `exec` untouched

`docker secret inspect` / `docker config inspect` stay hard-denied — those objects are secrets whole, so no template makes them safe.

## Acceptance

- The shared `PreToolUse` Bash guard enforces this (so it holds under `bypassPermissions`), not just the deny-list.
- Every `docker inspect` already used in the repo keeps working.
- A probe pins both the deny cases and the allow cases, and fails if the blanket block returns.
