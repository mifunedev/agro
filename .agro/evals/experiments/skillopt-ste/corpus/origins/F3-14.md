## Skill Definition

- **Name**: `interview`
- **Description**: Adaptive pre-work clarifier. Picks 2–4 task-specific questions via `AskUserQuestion`, echoes a 2–3 sentence scope brief, then proceeds. Refuses for trivial tasks.
- **Degrees of Freedom**: High — questions are picked per-task, not from a template bank.

## Purpose

The orchestrator currently has two ways to elicit user intent before non-trivial work: chat-based lettered questions (`/prd` Step 1) or paragraphs of free-text Q&A. Both work, but both consume context tokens and round-trips when the structured `AskUserQuestion` tool would let the user click 2–4 options once and unblock the work. No skill in this harness currently uses `AskUserQuestion`.

`/interview` reads conversation context, picks 2–4 task-specific questions (with bespoke options, not boilerplate), batches them into a single `AskUserQuestion` call, then echoes a 2–3 sentence scope brief and proceeds with the work. User can interrupt with **STOP** to redirect.

Intended outcome: cleaner kickoff for non-trivial tasks, fewer "guess and check" iterations, and an in-tree template that future skills can copy when they want structured elicitation.

## Examples

### Example 1 — refactor request

**User**: `/interview refactor the audit skill`
**Assistant**: Picks 2 questions ("which axis to change?" / "what does success look like?") with options referencing the actual audit skill (sub-agent prompts / synthesis step / trigger conditions), then echoes a scope brief naming the chosen axis and success signal.

### Example 2 — trivial task

**User**: `/interview fix typo in README`
**Assistant**: Announces skip — "Skipping interview — this looks trivial. Proceeding directly." — and continues with the work.

## Out of scope (v1)

- Auto-composition with `/prd` / `/ship-spec` (they keep their own clarifier).
- Multi-round interviews (one batched call; sequential is a rare documented exception).
- A rule mandating proactive `/interview` invocation before non-trivial work (separate decision).
