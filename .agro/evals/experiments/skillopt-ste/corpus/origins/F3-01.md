## Problem
Hourly autopilot runs created multiple ready PRs for the same `autopilot` issue (#432) because the selection gate only trusted GitHub linked-PR metadata / exact branch names. The duplicate PR bodies used `Closes #432`, but `gh pr view --json closingIssuesReferences` still returned empty on `development`-targeted PRs, so the next run considered #432 actionable again.

## Desired behavior
Before selecting or researching the next item, autopilot should enumerate current open PRs in the target repo and treat an open PR as in-flight for an issue when it references the issue number in the body/title/head branch (e.g. `feat/432-*`) even if GitHub linked-PR metadata is empty.

## Acceptance criteria
- The `/autopilot` queue check excludes an open issue when any open PR references it by issue number, head branch, title/body text, or GitHub linked metadata.
- `--dry-run` output surfaces dedupe state so operators can see why an issue was skipped.
- The behavior is covered by an eval probe or script test.
- Documentation explains the failure mode: development-targeted PRs may not populate linked-PR metadata before merge/default-branch close semantics.
