# PRD: Close secret-guard env leaks

Status: DRAFT

Issue: [#1150](https://github.com/mifunedev/agro/issues/1150) (#1152 merged into it)

## User Stories

### US-001: Deny jq filters that read the process environment

**Description:** As an operator, I want the Bash guard to deny a `jq` filter that reads `env` or `$ENV`, so that `jq` cannot print the process environment.

**Acceptance Criteria:**

- [ ] Before the hook change, `bash .agro/evals/probes/secret-exposure-guard.sh` exits 1 on `jq -n 'env'`. The evidence records the command and the exit status.
- [ ] The probe asserts `deny` for `jq -n 'env'`, `jq -n '$ENV'`, `jq -n env.HOME`, `jq -n '$ENV.PATH'`, and `jq -n '.a | env'`.
- [ ] The probe asserts `allow` for `jq '.env' .claude/settings.json`, `jq -r '.env // {}' .claude/settings.json`, `jq .env .claude/settings.json`, and `jq . my-env.json`.
- [ ] The probe builds each `env` and `$ENV` literal from parts, so that the probe source passes the guard.
- [ ] The probe `# source:` header names #1150.
- [ ] After the hook change, `bash .agro/evals/probes/secret-exposure-guard.sh` exits 0.
- [ ] The `DENY` reason text in `.agro/hooks/deny-env-dump.sh` names the `jq` `env` and `$ENV` reads.
- [ ] The Deny bullet in `docs/security-considerations.md` names the `jq` `env` and `$ENV` reads.

### US-002: Deny a single-quoted json format value in container inspect

**Description:** As an operator, I want the container-inspect guard to deny `--format 'json'` and `-f 'json'` so that an agent cannot print `Config.Env` through a single-quoted format value.

**Acceptance Criteria:**

- [ ] Before the hook change, `bash .agro/evals/probes/docker-inspect-env-guard.sh` exits 1 on `docker inspect --format 'json' web`. The evidence records the command and the exit status.
- [ ] The probe asserts `deny` for `docker inspect --format 'json' web`, `docker inspect -f 'json' web`, and `docker inspect --format='json' web`.
- [ ] The probe keeps its existing `deny` assertion for `docker inspect --format json web` and adds one for `docker inspect -f "json" web`.
- [ ] The `DOCKER_FMT_UNSAFE` term in `.agro/hooks/deny-env-dump.sh` contains no `\x27` sequence.
- [ ] After the hook change, `bash .agro/evals/probes/docker-inspect-env-guard.sh` exits 0.
- [ ] `CHANGELOG.md` `[Unreleased]` has one `### Fixed` entry that links #1150 and covers both stories.

## Summary

`.agro/hooks/deny-env-dump.sh` is the Bash `PreToolUse` guard. `.claude/settings.json` wires it to the `Bash` matcher. `.codex/hooks/deny-env-dump.sh` calls the shared hook through the `.claude/hooks` symlink, so Codex inherits each fix. #1149 (merged at `90707bd2`) added `mask_jq_filters` and the probe `.agro/evals/probes/secret-exposure-guard.sh`.

Verified current behavior (advisor run of the hook at `90707bd2`, jq 1.7):

| Command | Decision | Cause |
| --- | --- | --- |
| `jq -n 'env'` | allow | The bare-`env` `DENY` terms need a pipe, a redirect, or the end of the command after `env`. The closing quote blocks both. |
| `jq -n '$ENV'` | allow | No term matches `$ENV`. |
| `jq -n env.HOME`, `jq -n '$ENV.PATH'` | allow | Same causes. Each command prints one variable, and the variable can hold a secret. |
| `jq -n env` | deny | The `env[[:space:]]*$` term matches by accident. |
| `jq '.env' .claude/settings.json` | allow | Correct. #1149 fixed it. |
| `docker inspect --format 'json' web` | allow | Line 39 writes `["\x27]` inside a single-quoted bash string. `grep -E` reads the class as `"`, `\`, `x`, `2`, `7`. |
| `docker inspect -f 'json' web`, `docker inspect --format='json' web` | allow | Same cause. |
| `docker inspect --format json web`, `docker inspect -f "json" web` | deny | Correct. |

Selected approach:

1. Add one term to `DENY`. The term matches `jq` as a word, then any text, then one of two tokens. The first token is `$ENV`. The second token is the word `env`. The character before `env` must not be a letter, a digit, `_`, `.`, `$`, `/`, or `-`. `DENY` runs with `grep -i` on the original command string, so `mask_jq_filters` does not hide the filter.
2. Rewrite the `json` term of `DOCKER_FMT_UNSAFE` so that its quote class holds a real `"` and a real `'`. Build the term with bash quoting, not with `\x27`.

## Architectural Decisions

- The shared hook stays the single source of truth. The Codex wrapper and the `.claude/hooks` symlink need no change.
- The `jq` term lives in `DENY` and reads the original command string. The `jq` filter exemption from #1149 applies to the secret-path check only, so the exemption does not hide the new term.
- The `jq` term scans from `jq` to the end of the command. A quote-aware parse of the filter adds machinery, and a stop at `|` misses `jq -n '.a | env'`. The cost is a false deny on a later `env` word, such as `jq . a.json | grep env`. The guard accepts that cost: a false deny is safe, and a false allow leaks secrets.
- The `.`, `/`, and `-` exclusions keep `.env` field reads and paths such as `my-env.json` or `/srv/env/a.json` allowed. The `$` exclusion stops a double match on `$ENV`. Because `DENY` runs with `grep -i`, a `jq` variable named `$env` is denied. The guard accepts that false deny.

## Design Principles

- Deny on doubt. A parse gap produces a false deny, never a false allow.
- One source of truth: `.agro/hooks/deny-env-dump.sh`.
- Change the smallest set of patterns that closes the reported false allows.
- Add no explanatory comments to the hook (root `AGENTS.md`, non-negotiable 5).
- List what each changed pattern allowed before the change, then confirm that each listed shape still has the intended decision (#1149 lesson).

## Out of Scope

- A `jq` program that reads `env` from a file through `-f` or `--from-file`. The guard cannot read the file content.
- `yq` environment operators such as `env()` and `strenv()`. `yq -n 'strenv(HOME)'` stays allowed.
- `gojq`, `jaq`, and other `jq` implementations.
- `.agro/hooks/deny-secret-paths.sh`.
