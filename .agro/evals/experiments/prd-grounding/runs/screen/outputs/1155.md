# PRD: Close the secret-guard interpreter and search-pattern gaps

Status: DRAFT

## User Stories

### US-001: Deny interpreter reads of the process environment

**Description:** As an operator, I want the Bash guard to deny interpreter code that reads the process environment so that an agent cannot print secrets.

**Acceptance Criteria:**

- [ ] Before the hook change, `bash .agro/evals/probes/secret-exposure-guard.sh` exits 1 on the `python3 -c` case. The evidence records the command and the exit status.
- [ ] The probe asserts `deny` for `python3 -c 'import os; print(dict(os.environ))'` and `perl -e 'print "$_=$ENV{$_}\n" for keys %ENV'`.
- [ ] The probe asserts `deny` for `python3 -c 'import os; print(os.getenv("HOME"))'`, `node -e 'console.log(process.env)'`, and `node -p process.env`.
- [ ] The probe asserts `allow` for `python3 -c 'print(1)'` and `python3 script.py`.
- [ ] The probe holds each environment-access token in a shell variable, per the file-fixture driver rule in `.agro/evals/AGENTS.md`.
- [ ] A new deny reason names interpreter environment reads. The reason differs from the bulk-dump reason.
- [ ] After the hook change, `bash .agro/evals/probes/secret-exposure-guard.sh` exits 0.

### US-002: Allow a search pattern that names `.env`

**Description:** As an agent, I want the secret-path check to skip the pattern operand of `grep` and `rg` so that a search for `process.env` in source code runs.

**Acceptance Criteria:**

- [ ] Before the hook change, `bash .agro/evals/probes/secret-exposure-guard.sh` exits 1 on `grep process.env src/index.ts`. The evidence records the command and the exit status.
- [ ] The probe asserts `allow` for `grep process.env src/index.ts`, `grep "Config.Env" .claude/settings.json`, `rg 'process\.env' src`, and `grep -rn import.meta.env src`.
- [ ] The probe asserts `deny` for `grep TOKEN .env`, `grep -r TOKEN ./app/.env`, `grep -f .env src/index.ts`, `grep x < .env`, and `cat .env | grep x`.
- [ ] The probe asserts `deny` for `rg TOKEN .env.local` and `rg --file .env src`.
- [ ] Every US-001 `node` assertion still returns `deny` after the US-002 hook change.
- [ ] Every assertion that existed before this task still passes.
- [ ] After the hook change, `bash .agro/evals/probes/secret-exposure-guard.sh` exits 0.
- [ ] `docs/security-considerations.md` lists interpreter environment reads under the command guard deny tier.
- [ ] `docs/security-considerations.md` states that the path tier skips the pattern operand of `grep` and `rg`.
- [ ] `CHANGELOG.md` `[Unreleased]` `### Fixed` has one entry that links #1155. The entry is at most 250 characters.

## Summary

`.agro/hooks/deny-env-dump.sh` is the Bash `PreToolUse` guard. `.claude/hooks` is a symlink to `.agro/hooks`. `.codex/hooks/deny-env-dump.sh` calls the same file.

The advisor fed each command to the hook on `development` at `27edb569` on 2026-09-26. The advisor used a file-fixture driver.

| Command | Decision | Cause |
| --- | --- | --- |
| `python3 -c` with `dict(os.environ)`, `os.environ`, or `os.getenv` | allow | No term reads interpreter code. |
| `perl -e` with `%ENV` or `$ENV{HOME}` | allow | No term reads interpreter code. |
| `node -p process.env` | allow | No term reads interpreter code. |
| `node -e 'console.log(process.env)'` | deny | `READ_CMD` contains `\.`. That alternative matches the `.` in `console.log`. `SECRET_PATH` then matches `.env` in `process.env`. |
| `grep process.env src/index.ts`, `grep "Config.Env" <file>`, `rg 'process\.env' src` | deny | `SECRET_PATH` matches `.env` at any position, case-insensitive. |
| `grep TOKEN .env`, `grep -r TOKEN ./app/.env`, `cat .env` | deny | Expected. |
| `jq --arg n 'notes: docker inspect web' -n '$n'` | deny | `DOCKER_INSPECT` matches the argument text. |

The `node` deny is accidental. A fix to the secret-path check alone turns the `node` case into an allow. US-001 therefore lands first and adds an explicit interpreter check.

Selected approach:

1. Add an interpreter check. Deny when a `python`, `python3`, `perl`, or `node` command contains `os.environ`, `os.getenv`, `%ENV`, `$ENV{`, or `process.env` before the next `;`, `&`, or `|`. The check emits its own deny reason.
2. Extend the existing operand mask to `grep` and `rg`. The hook masks the first operand of each call before the secret-path check. The hook keeps the operand when a flag loads a pattern file, the same rule as `JQ_PATH_FLAG`. A file argument that names `.env` stays in the text, so the check still denies it.

## Architectural Decisions

- The shared hook stays the single source of truth.
- The interpreter check denies a single value read, such as `os.getenv("HOME")`, as well as a full dump. This decision follows the #1150 `jq` decision: the guard cannot tell a secret name from a safe name.
- The interpreter check does not require a `-c`, `-e`, or `-p` flag. A script file path that contains an environment token is a rare false deny. The check accepts that cost.
- The operand mask generalizes the existing `mask_jq_filters` parse. The task adds no second parser.
- When a flag that takes a value, such as `-A 3`, precedes the pattern, the mask can hide the wrong operand. The pattern then stays in the text. The result is a false deny, never a false allow.
- `-e <pattern>` is a pattern, so the mask hides the value of the first `-e`. A later file argument stays in the text.
- `JQ_ENV_READ` keeps reading `jq` filter text only. The `grep` and `rg` mask feeds `path_cmd` only.

## Design Principles

- Deny on doubt. A parse gap produces a false deny, never a false allow.
- One source of truth: `.agro/hooks/deny-env-dump.sh`.
- Change the smallest set of patterns that closes the two reported gaps.
- Add no explanatory comments to the hook (root `AGENTS.md`, non-negotiable 5).
- Hold sensitive fixture text in shell variables. A literal token in an agent command triggers the guard.

## Out of Scope

- `ruby`, `deno`, `bun`, and other interpreters.
- Interpreter code that a HEREDOC supplies, such as `python3 - <<EOF`. The guard strips HEREDOC bodies by design.
- Interpreter code in a script file.
- `sed` and `awk` programs that name `.env`, such as `sed -n '/process.env/p' <file>`.
- Argument text that only names a guarded command, such as notes passed to `jq --arg`. The `DOCKER_INSPECT` term causes that deny, not the secret-path check. The #1150 lessons record the workaround: pass the notes through `--rawfile`. See open question 1.
- The `env` word terms in `DENY`, such as `grep -e secret|env|guard`. That text matches the `env` followed by `|` term.
