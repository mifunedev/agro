# PRD: Pre-release publishing

Status: DRAFT

## User Stories

### US-001: Accept and reserve pre-release versions

**Description:** As the operator, I want the release reservation to accept a `MAJOR.MINOR.PATCH-<label>.<n>` version so that an `experiment/**` push can reserve a pre-release.

**Acceptance Criteria:**

- [ ] `parseSemVer("0.14.0-minimal.1")` returns `{ major: 0, minor: 14, patch: 0, label: "minimal", number: 1, prerelease: true }`.
- [ ] `parseSemVer("0.14.0")` returns `label: null`, `number: null`, and `prerelease: false`.
- [ ] `parseSemVer` throws `INVALID_SEMVER_VERSION` for each of `0.14.0-rc`, `0.14.0-rc.01`, `0.14.0-Rc.1`, `0.14.0-a.b.1`, `0.14.0-latest.1`, and `0.14.0+build.1`.
- [ ] For a pre-release version, `reserveGitHubRelease` sends `prerelease: true` in the draft-release `POST /releases` body. For a stable version, the body holds `prerelease: false`.
- [ ] `githubOutputLines` writes `prerelease=true|false` and `distTag=<label>|latest`.
- [ ] `pnpm test:scripts .agro/scripts/__tests__/release-reservation.test.ts` exits 0.

### US-002: Trigger on experiment branches with a stable-version guard

**Description:** As the operator, I want `release.yml` to run on `experiment/**` pushes so that an experiment branch publishes pre-releases, and an unbumped push stays a green no-op.

**Acceptance Criteria:**

- [ ] The `on.push.branches` list of `.github/workflows/release.yml` holds `main`, `master`, and `experiment/**`, and holds no `tags:` key.
- [ ] The `reserve` step passes `RELEASE_BRANCH: ${{ github.ref_name }}` to `reserve-github-release.mjs`.
- [ ] If `RELEASE_BRANCH` is not `main` or `master` and the version is stable, `reserveGitHubRelease` returns `publishedNoop: true` with `reservationKind: "stable-on-noncanonical"`. The function sends no GitHub API request in this case.
- [ ] If the version is a pre-release and its `v<version>` tag already points at another commit, the result is `reservationKind: "already-released"` and `publishedNoop: true`.
- [ ] `pnpm test:scripts .agro/scripts/__tests__/release-reservation.test.ts` exits 0.

### US-003: Never make a pre-release latest

**Description:** As the operator, I want a pre-release to stay off every `latest` channel so that stable users never receive experiment builds.

**Acceptance Criteria:**

- [ ] In `check` mode, `promote-release-latest.sh` writes `makeLatest=false` when `RELEASE_VERSION` holds a pre-release. This rule applies on every branch, `main` included.
- [ ] In `promote` mode, `promote-release-latest.sh` exits 0 for a pre-release `RELEASE_VERSION` and calls no `docker` command.
- [ ] The `finalize` job passes `RELEASE_VERSION` to the `promote-release-latest.sh check` step.
- [ ] The `updateRelease` call in `finalize` sends `prerelease: true` for a pre-release and `prerelease: false` for a stable release.
- [ ] `pnpm test:scripts .agro/scripts/__tests__/release-latest.test.ts .agro/scripts/__tests__/release-reservation.test.ts` exits 0.

### US-004: Publish npm pre-releases under the label dist-tag

**Description:** As the operator, I want `publish-cli.yml` to publish a pre-release under the dist-tag `<label>` so that `npm install @mifune/agro` keeps resolving the stable version.

**Acceptance Criteria:**

- [ ] The guard step in `.github/workflows/publish-cli.yml` derives the dist-tag from `.agro/cli/package.json`: `<label>` for a pre-release and `latest` for a stable version.
- [ ] The publish step runs `npm publish --access public --provenance --tag <dist-tag>`.
- [ ] If the CLI version is a pre-release and its label is `latest`, the guard step exits 1 before `npm publish`.
- [ ] The fake-npm harness in `canonical-publish-contract.test.ts` records `publish --access public --provenance --tag minimal` for version `9.9.9-minimal.1`, and records `--tag latest` for version `9.9.9`.
- [ ] `pnpm test:scripts .agro/scripts/__tests__/canonical-publish-contract.test.ts` exits 0.

### US-005: Keep pre-releases off the docs site and document the procedure

**Description:** As the operator, I want pre-releases to skip the docs-site dispatch and to have a documented procedure so that `agro.mifune.dev` keeps the stable CLI.

**Acceptance Criteria:**

- [ ] The `notify-docs` job condition holds `needs.reserve.outputs.prerelease != 'true'`.
- [ ] `.agro/skills/release/SKILL.md` has a section that names the version form `MAJOR.MINOR.PATCH-<label>.<n>`, the `experiment/**` trigger, the `<label>` dist-tag, and the rule that a pre-release never becomes `latest`.
- [ ] `CHANGELOG.md` has an `[Unreleased]` entry for pre-release publishing.
- [ ] `bash .agro/skills/ste/scripts/ste-check.sh .agro/skills/release/SKILL.md` exits 0.
- [ ] `bash .agro/skills/eval/run.sh` reports no REGRESSION.

## Summary

Verified current state:

- `.github/workflows/release.yml` runs on pushes to `main` and `master` only. Root `package.json` holds the release version, which is `0.14.0`. The tag `v0.14.0` exists on `origin`.
- `.agro/scripts/release-reservation.mjs` accepts only `MAJOR.MINOR.PATCH`. The pattern `SEMVER_PATTERN` rejects every pre-release form.
- `.agro/scripts/reserve-github-release.mjs` creates each draft with `prerelease: false`.
- `.agro/scripts/promote-release-latest.sh` gates `latest` on the canonical branch head. In `promote` mode, the script exits 64 for a version that is not `MAJOR.MINOR.PATCH`. A pre-release on `main` would fail the `publish-image` job at that step.
- `.github/workflows/publish-cli.yml` runs `npm publish --access public --provenance` with no `--tag`. npm then moves the `latest` dist-tag to the published version.
- `notify-docs` sends `agro-release` with the release SHA. The docs site builds `agro.js` and mirrors the installers from that ref (`.agro/knowledge/source/agro-web-pipeline.md`).
- `origin/experiment/minimal-core` holds version `0.15.0-minimal.1`. That branch already adds `experiment/**` to the trigger of its copy of `release.yml`. This task lands the full change on the development line. The experiment branch picks the change up through a merge.

Selected approach: derive one fact, "pre-release or stable", from the version string. Each channel reads that fact: the GitHub Release flag, `make_latest`, GHCR `latest`, the npm dist-tag, and the docs dispatch. The branch decides only one rule: a stable version on a branch other than `main` or `master` never reserves a tag.

## Architectural Decisions

- **Source of truth:** root `package.json` `version` stays the only release version. The version string alone decides pre-release status. No new input, file, or environment variable holds that status.
- **Accepted form:** `MAJOR.MINOR.PATCH-<label>.<n>`. `<label>` matches `[a-z][a-z0-9-]*` and is not `latest`. `<n>` matches `0|[1-9][0-9]*`. The parser rejects every other pre-release form and all build metadata. The strict form keeps `<label>` a valid npm dist-tag.
- **Branch rule:** if a push to a branch other than `main` or `master` carries a stable version, the `reserve` job reports a green no-op. This rule keeps an experiment branch from claiming the next stable tag.
- **One parser:** `reserve-github-release.mjs` and `publish-cli.yml` both read the version through `parseSemVer`, or through a pattern that a test proves equal to `SEMVER_PATTERN`. `promote-release-latest.sh` uses a bash pattern that a test pins to the same accepted and rejected examples.
- **Fail closed:** a pre-release never reaches `latest`, even on `main`. The check keys on the version and not on the branch.
- **Docs gate:** `notify-docs` skips pre-releases. The docs site mirrors the CLI from the dispatched ref, so a dispatch would serve an experiment CLI at `agro.mifune.dev`.
- **Auth and scoping:** no change. The jobs keep their current `permissions` blocks and secrets.

## Design Principles

- Follow `AGENTS.md`: the application agent writes the code in the sandbox, and tracked code gets no explanatory comments.
- Derive every channel decision from the version string. Add no second switch.
- Fail closed on each `latest` channel.
- Keep the change inside the current pipeline. Add no new workflow file.
- Reuse the existing test harnesses: the fake `fetch`, the fake `docker`, and the fake `npm`.

## Out of Scope

- Tag-push triggers.
- A `workflow_dispatch` release path in `release.yml`.
- Moving GHCR channel tags, for example `:minimal` or `:rc`.
- `mifunedev/agro-web` documentation.
- Changes to `get-agro.sh`. The installer reads `releases/latest`, and a pre-release never becomes latest.
- Cleanup of old pre-release tags, releases, images, or dist-tags.
