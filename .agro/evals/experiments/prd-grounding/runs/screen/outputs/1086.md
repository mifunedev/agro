## User Stories

### US-001: Shared workspace helpers

**Description:** As the implementation owner, I want one module to list workspaces and build the refusal so that three commands share one definition.

**Acceptance Criteria:**

- [ ] `.agro/cli/src/lib/host-workspace.ts` exports `listHostWorkspaces(env, home)`.
- [ ] `listHostWorkspaces` returns each directory under `workspacesRoot(env, home)` whose name matches `SANDBOX_NAME_PATTERN` and that holds `.git`, sorted by name.
- [ ] `listHostWorkspaces` returns `[]` when `workspacesRoot(env, home)` does not exist.
- [ ] `listHostWorkspaces` skips a directory with no `.git` and a directory whose name fails `SANDBOX_NAME_PATTERN`.
- [ ] `.agro/cli/src/lib/host-workspace.ts` exports `missingWorkspaceRefusal(bin, verb, root, env, home)`.
- [ ] The refusal text contains `${bin} workspace create` and the resolved root.
- [ ] The refusal text names every workspace that `listHostWorkspaces` returns, or states that no workspace exists.
- [ ] `pnpm vitest run .agro/cli/src/lib/__tests__/host-workspace.test.ts` exits 0.

### US-002: `agro workspace create`

**Description:** As an operator, I want `agro workspace create [<name>] [--path <dir>]` to clone `mifunedev/agro` into a workspace so that I can create a workspace without installing a harness or a tool.

**Acceptance Criteria:**

- [ ] `agro workspace create` with no argument clones `AGRO_REPO_URL` into `~/.agro/workspaces/default` through `ensureHostWorkspace` and exits 0.
- [ ] `agro workspace create acme` clones into `~/.agro/workspaces/acme` and exits 0.
- [ ] `agro workspace create --path <dir>` clones into the absolute form of `<dir>` and exits 0.
- [ ] A `<name>` together with `--path` exits 1 and clones nothing.
- [ ] A name that fails `assertWorkspaceName` exits 1 with the `invalid workspace name` message and clones nothing.
- [ ] A root that already holds `.git` prints `host workspace reused at <root>`, runs no `git clone`, and exits 0.
- [ ] A split or legacy state home exits 1 with the `stateHomeRefusal` text and clones nothing.
- [ ] A `--path` equal to the state home exits 1 with the `stateHomeRootRefusal` text and clones nothing.
- [ ] After `create` exits 0, `~/.agro/config.json` holds the same `harnessRoot` value as before the run. When the file was absent, the file stays absent.
- [ ] A failed clone exits 1 and prints the `could not clone` message.

## Summary

Verified current state:

- `installOnHost` in `.agro/cli/src/commands/harness.ts:341` resolves a root, asks `Workspace name [default]:` on an interactive first run, then calls `ensureHostWorkspace` (lines 396-424).
- `installOnHost` in `.agro/cli/src/commands/tool.ts:379` asks `Harness root [<root>]:` for a free-form path, then calls `ensureHostWorkspace` (lines 437-455).
- Both install paths write `harnessRoot` and a receipt with `workspaceRoot` after a successful install (`harness.ts:478-497`, `tool.ts:480-499`).
- `ensureHostWorkspace` in `.agro/cli/src/lib/host-workspace.ts` clones into an absent or empty root and reuses a root that holds `.git`.
- `workspacesRoot`, `workspaceRoot`, `assertWorkspaceName`, `resolveHarnessRoot`, and `DEFAULT_WORKSPACE_NAME` live in `.agro/cli/src/lib/host-config.ts`.
- `listEntries` in `.agro/cli/src/lib/registry.ts:44` scans `~/.agro/sandboxes/` by name pattern and a marker file. `listHostWorkspaces` follows that pattern, with `.git` as the marker.
- `cli.ts` dispatches `harness` at line 1389 and `tool` at line 1426. No `workspace` verb exists.

Selected approach:

1. Add `listHostWorkspaces` and `missingWorkspaceRefusal` to `host-workspace.ts`.
2. Add `.agro/cli/src/commands/workspace.ts` with `runWorkspaceCreate` and `runWorkspaceList`. `runWorkspaceCreate` calls `ensureHostWorkspace`. The command writes no host config.
3. Add the `workspace` verb to `cli.ts`: parser, help page, top-level usage line, and dispatch.
4. In both `installOnHost` functions, replace the clone step with an existence check on `<root>/.git`. Remove the second interactive prompt.
5. Update help text, docs, and `CHANGELOG.md`.

## Storage

The change adds no storage. A workspace stays a git checkout at `~/.agro/workspaces/<name>/` or at a `--path` directory. `~/.agro/config.json` keeps its schema. `harnessRoot` and the receipts keep their writers: the two install paths. `workspace list` derives its rows from the file system on each run, as `registry.listEntries` does.

## Architectural Decisions

- **Source of truth:** A directory is a workspace when the directory holds `.git`. `ensureHostWorkspace` already uses that marker for reuse.
- **Default workspace:** The default is the root that `resolveHarnessRoot(undefined, env, home)` returns: the recorded `harnessRoot`, else `~/.agro/workspaces/default`. `list` marks that root, and an install without a flag uses that root.
- **Single writer of `harnessRoot`:** `create` never writes `config.json`. A first host install after `create` records `harnessRoot`, as today.
- **Idempotent create:** `create` against a root that holds `.git` reports reuse and exits 0. This matches `ensureHostWorkspace`.
- **Execution location:** The door runs where `agro` runs. The door needs no Docker and no sandbox.
- **Guards:** `create` applies `stateHomeRefusal` and `stateHomeRootRefusal` before any clone, as the install paths do.

## Design Principles

- One door per lifecycle action. `agro workspace create` is the only command that clones a host workspace.
- Reuse `ensureHostWorkspace`. Do not add a second clone path.
- Follow the `registry.listEntries` scan. Add no registry file.
- Keep install behavior on an existing workspace byte-identical, apart from the removed clone lines.
- Add no comments to tracked code, per `AGENTS.md`.

## Out of Scope

- `agro workspace use`, `agro workspace status`, and `agro workspace remove`.
- A `--default` flag on `create`.
- `--workspace <name>` on `tool install`.
- A new registry file.
- Changes to `harness uninstall`, `tool uninstall`, `harness status`, or `tool status`.
- Migration of a workspace that an earlier install created. Each such workspace holds `.git` and keeps working.
- Closing #1070. The RFC stays open.
