# PRD: Secret guard false positives

Status: DRAFT

Source: issue #1149. Related: #1147, PR #1148.

## User Stories

### US-001: Match shell-history access by command position

**Description:** As an agent, I want the Bash guard to allow `history` in a quoted argument so that my commit message stays accurate.

The guard must still deny shell-history access.

**Acceptance Criteria:**

- [ ] `.agro/hooks/deny-env-dump.sh` returns no decision for `git commit -m "record history of X"`.
- [ ] `.agro/hooks/deny-env-dump.sh` returns no decision for `git commit -m "apply task-history signal"`.
- [ ] `.agro/hooks/deny-env-dump.sh` returns `deny` for `history`, for `history | tail`, and for `ls; history`.
- [ ] `.agro/hooks/deny-env-dump.sh` returns `deny` for `fc -l`.
- [ ] `.agro/hooks/deny-env-dump.sh` returns `deny` for `cat ~/.zsh_history` and for `tail ~/.bash_history`.
- [ ] `.claude/settings.json` has no `permissions.deny` entry `Bash(command=*history*)`.
- [ ] `.claude/settings.json` has a `permissions.deny` entry that matches a command that starts with `history`.

### US-002: Match `.env` file paths, not jq filter keys

**Description:** As an agent, I want the Bash guard to allow a `jq` or `yq` filter key named `env` so that I can read `.claude/settings.json`.

The guard must still deny `.env` file reads.

**Acceptance Criteria:**

- [ ] `.agro/hooks/deny-env-dump.sh` returns no decision for `jq '.env' .claude/settings.json`.
- [ ] `.agro/hooks/deny-env-dump.sh` returns no decision for `jq '.env // {}' .claude/settings.json`.
- [ ] `.agro/hooks/deny-env-dump.sh` returns no decision for `jq -r '.env.FOO' .claude/settings.json`.
- [ ] `.agro/hooks/deny-env-dump.sh` returns `deny` for `cat .env`, for `jq . .env`, and for `jq '.x' .devcontainer/.env`.
- [ ] `.agro/hooks/deny-env-dump.sh` returns no decision for `cat .example.env`.

### US-003: Pin both guard boundaries in a probe

**Description:** As the advisor, I want a Tier-A probe for US-001 and US-002 so that a later guard change cannot reopen either defect.

**Acceptance Criteria:**

- [ ] `.agro/evals/probes/secret-exposure-guard.sh` exists and declares `# tier: A`, `# source:`, and `# desc:` headers.
- [ ] `bash .claude/skills/eval/run.sh --probe secret-exposure-guard` reports PASS.
- [ ] The probe exits 1 and names the failed case when the `history` pattern in a disposable copy of the hook reverts to `\bhistory\b`.
- [ ] The probe exits 1 and names the failed case when a disposable copy of the hook drops the `.env` path match.
- [ ] `bash .claude/skills/eval/run.sh --probe docker-inspect-env-guard` reports PASS.
- [ ] `bash .claude/skills/eval/run.sh --probe operator-config-guard` reports PASS.

## Summary

Verified current state:

- `.agro/hooks/deny-env-dump.sh:23` adds `\bhistory\b` to `DENY`. The hook matches `DENY` against the full command text. Any command that contains the word `history` gets `deny`, a quoted commit message included. This planning session reproduced the defect: a `grep` for the word `history` got `deny`.
- `.agro/hooks/deny-env-dump.sh:42` starts `SECRET_PATH` with `\.env[^[:space:]/"']*`. `SECRET_PATH_DENY` at line 73 accepts any text between a read command and the path. In `jq '.env // {}' .claude/settings.json`, `jq` matches `READ_CMD` and the filter text `.env` matches `SECRET_PATH`. The basename allowlist at lines 100-110 does not exempt `.env`, so the hook returns `deny`.
- `SECRET_PATH` already lists `.bash_history`, `.zsh_history`, `.psql_history`, `.python_history`, and `.node_repl_history`. A read command on a history file stays denied without the bare-word `history` pattern.
- `.claude/settings.json` holds `Bash(command=*history*)` in `permissions.deny`. That rule matches the same benign commit messages. The rule also needs a change.
- `.codex/hooks/deny-env-dump.sh` pipes into `.claude/hooks/deny-env-dump.sh`. `.claude/hooks` is a symlink to `.agro/hooks`. Codex gets the fix with no Codex change.
- Two probes drive the hook today: `.agro/evals/probes/docker-inspect-env-guard.sh` and `.agro/evals/probes/operator-config-guard.sh`. No probe pins the `history` case or the `.env` case.

Selected approach:

1. Replace `\bhistory\b` with a command-position match. The pattern matches `history` at the start of the command. The pattern also matches `history` after `;`, `&`, `|`, `(`, `{`, `$(`, or a backtick. Optional whitespace and an optional `builtin` prefix can come before `history`. Keep `\bfc[[:space:]]+-l`.
2. Before the `SECRET_PATH_DENY` match, remove the filter expression that follows `jq` or `yq`. The filter expression is the first quoted argument after the command name and its options. A file path argument stays in the text, so `jq . .env` stays denied.
3. Replace `Bash(command=*history*)` in `.claude/settings.json` with `Bash(command=history*)`. Keep the `*cat*.bash_history*` and `*cat*.zsh_history*` entries.
4. Add one probe that pins each allow and deny case.

## Architectural Decisions

- `.agro/hooks/deny-env-dump.sh` stays the one source of truth for the Bash guard. Claude Code and Codex call the file through the `.claude/hooks` symlink.
- The guard matches shell-history access by command position and by file path, not by a bare word.
- The guard matches `.env` as a file argument, not as text inside a `jq` or `yq` filter.
- Commands that do not contain `history`, `jq`, or `yq` get the same decision as before.
- A non-interactive Bash shell keeps no command history, so `history` inside a `bash -c` string prints no stored command. Open question 1 records this residual case.

## Design Principles

- Change the canonical `.agro/hooks/` file. Do not patch `.claude/hooks` or `.codex/hooks`.
- Do not add explanatory comments to tracked code.
- Keep the smallest regex change that separates access from mention.
- Do not weaken a deny case to fix a false positive. Each deny case in the probe must stay `deny`.

## Out of Scope

- The guard that denied `git checkout --` in #1147. That guard is `cc-safety-net`, an external tool.
- Other bare-word patterns in `DENY`, for example `set` or `env`.
- `.agro/hooks/deny-secret-paths.sh`. That hook matches `file_path` values, not command text.
- A shell parser for the hook.
- Deny reason text changes.

## Open Questions
