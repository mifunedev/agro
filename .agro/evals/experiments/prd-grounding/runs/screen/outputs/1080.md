# PRD: Installation-aware missing lifecycle script diagnostic

Status: BLOCKED

Source: `work/issue-1080.md`.

## User Stories

### US-001: Name the recovery that works for the running installation

**Description:** As an operator, I want a supported recovery in the missing script error so that I do not follow a refused command.

**Acceptance Criteria:**

- [ ] For an image installation, the `requireLifecycleScript` error names the host image refresh: `agro stop <name>`, then `agro sandbox install docker --name <name>`.
- [ ] For an image installation, the error text does not contain `` `agro update` `` and does not contain `` `oh update` ``.
- [ ] For an npm, standalone, source, legacy-package, or unknown installation, the error names `oh update` as the verb that re-vendors the control plane.
- [ ] For each installation kind, the error text does not contain `` `agro update` ``.
- [ ] The error text starts with `missing lifecycle script <absolute script path>`, so the regex `/missing lifecycle script/` in `migrate-rehearsal.test.ts` still matches.
- [ ] The new test cases fail against the current message at `.agro/cli/src/lib/execution/runner.ts:75`.
- [ ] The new test cases pass after the change.
- [ ] `npm --prefix .agro/cli run typecheck` exits 0.
- [ ] `npx vitest run .agro/cli` exits 0 from the repository root.

### US-002: Name a generation mismatch

**Description:** As an operator, I want the error to name the other generation's existing control directory so that I diagnose version skew.

**Acceptance Criteria:**

- [ ] BLOCKED on Open Question 1. The operator selects option A or option B before this story starts.
- [ ] Option A: a test builds a root where the other generation's control directory exists. The error names that directory path and the generation of the resolved directory.
- [ ] Option A: when the other generation's control directory is absent, the error omits the mismatch clause.
- [ ] Option B: the story is removed from `prd.json`. The US-003 runbook covers the mismatch.

### US-003: Document recovery for a sandbox already in this state

**Description:** As an operator with a sandbox that already shows `missing lifecycle script /home/sandbox/harness/.oh/scripts/gateway.sh`, I want a runbook so that I recover without mutating `/opt/oh` on a running sandbox.

**Acceptance Criteria:**

- [ ] `docs/repair-missing-lifecycle-script.md` exists.
- [ ] The runbook quotes the exact error line from the issue.
- [ ] The runbook gives a diagnosis step that runs `agro --version` inside the sandbox and runs `readlink -f /usr/local/bin/agro`.
- [ ] The runbook states that a bundle below `<first version that resolves both generations>` reads only `.oh/`.
- [ ] The runbook gives the host image refresh procedure and names the context (host) of each command.
- [ ] The runbook states that `agro update` refuses an image installation, and names `oh update` as the payload vendoring verb.
- [ ] The runbook contains no step that writes to `/opt/oh`, creates a `.oh` symlink, or changes Slack credentials.
- [ ] `docs/README.md` links the runbook next to the other `repair-*.md` runbooks.
- [ ] `bash .agro/skills/ste/scripts/ste-check.sh docs/repair-missing-lifecycle-script.md` exits 0.

## Summary

Verified current state:

- `.devcontainer/Dockerfile:53-57` copies `.agro/cli/` to `/opt/oh/`. The Dockerfile links `/usr/local/bin/agro` to `/opt/oh/dist/agro.js`.
- The reported failure comes from an old image bundle at v0.9.0. That bundle reads only `<root>/.oh/scripts/`. Current source is `@mifune/agro` v0.12.2 (`.agro/cli/package.json`).
- `requireLifecycleScript` (`.agro/cli/src/lib/execution/runner.ts:70-79`) resolves the control directory through `resolveProjectLayout`. The path defect is fixed in current source.
- The error message at `runner.ts:75` tells the operator to run `` `${activeBin()} update` ``. Under `agro`, `update` is CLI self-upgrade (`.agro/cli/src/cli.ts:1253-1281`). `oh update` vendors the payload.
- `classifyInstallation` returns `{ kind: "image" }` for a target under `/opt/oh/` (`.agro/cli/src/commands/self-upgrade.ts:70`, `:117`). `refuseUnsupported` then refuses the upgrade (`self-upgrade.ts:185-191`).
- The test at `.agro/cli/src/__tests__/compose-verbs.test.ts:124-139` asserts the wrong hint `` `${bin} update` ``. This change replaces that assertion.

Selected approach:

1. `requireLifecycleScript` calls `classifyInstallation(process.argv[1], deps)`. The function then selects the recovery text by `kind`.
   `VERSION` is private to `.agro/cli/src/cli.ts:66`, and `classifyInstallation` reads no version. The owner passes `defaultDeps` a fixed placeholder version, or narrows the classifier's dependency type.
2. The recovery text for `image` reuses the host refresh procedure that `refuseUnsupported` already prints. One helper owns that text, and both call sites use it.
3. All other kinds name `oh update`.
4. A new runbook documents recovery for a sandbox that already runs an old bundle. A source change cannot reach that bundle.

## Architectural Decisions

- `classifyInstallation` stays the single source of truth for the installation kind. The diagnostic does not repeat the `/opt/oh/` prefix check.
- One helper owns the image refresh procedure text. `refuseUnsupported` and `requireLifecycleScript` both call that helper.
- `runner.ts` in `lib/execution/` imports from `commands/self-upgrade.ts`. If the implementation owner rejects a `lib` to `commands` import, the owner moves `classifyInstallation` and its dependencies to `lib/` in the same change. The owner records the choice in `progress.txt`.
- The change adds no ownership change, no lifecycle change, no `.oh` to `.agro` symlink, and no boot-time refresh of `/opt/oh`.

Affected surfaces:

- Host and sandbox: applied. The CLI change is source. The runbook names host and sandbox commands.
- Lifecycle door: applied. Every verb that calls `requireLifecycleScript` gets the same message.
- Canonical and provider surfaces: applied. The change lives in `.agro/cli/`. No provider mirror changes.
- Root and scaffold: applied. The CLI bundle ships to initialized projects through the image and npm.
- Interactive and headless processes: not applicable. No process starts.
- Local and remote operation: not applicable. The message has no terminal dependency.
- Parallel operation: not applicable. The diagnostic holds no mutable state.
- Public documentation: open. See Open Question 3.
- Verification: applied. See the Test Plan.

## Design Principles

- Apply the repository principles in `AGENTS.md`: code is the source of truth, one source of truth per policy, and YAGNI.
- Add no comments to tracked code.
- Tell the operator a recovery that the running installation accepts. Never print a command that the same CLI refuses.
- Keep the error prefix stable, because tests and operators match on it.

## Out of Scope

- A `.oh` to `.agro` symlink.
- Automatic boot-time installation or refresh of `/opt/oh`. That change alters ownership and needs architecture review and operator approval.
- Any change to Slack credentials.
- Any write to `/opt/oh` on a running sandbox.
- Any change to `agro update` or `oh update` behavior.
- A new image release. The release follows the normal `/release` path.
