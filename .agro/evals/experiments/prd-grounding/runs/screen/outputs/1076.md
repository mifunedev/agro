## Summary

Issue #1076 asks for a reusable `/council` skill. The skill runs a bounded deliberation among independent perspectives. The council compares designs before implementation. The council can use local Claude and Pi traces as evidence without a publish of private session content.

Verified current state:

- No `.agro/skills/council/` directory exists. `.claude/skills` and `.agents/skills` are symlinks to `.agro/skills`, so a new canonical skill needs no mirror.
- `/strategic-proposal` already runs a council, but only for a roadmap and a V2MOM. A general design council has no owner.
- `/weigh` selects among sampled trajectories with a deterministic scorer. `/weigh` does not deliberate over designs.
- `/prompt-miner` owns `mine-traces.mjs`. The engine reads `~/.claude/projects/-home-sandbox-harness` and `$PI_CODING_AGENT_DIR` or `~/.pi/agent/sessions`. The engine writes only to `$TMPDIR/oh-prompt-miner/<UTC-date>/` and omits prompt text by default.
- `roles-are-skills.sh` fails when a `council.md` project agent appears. The council must stay a skill.
- Commit `5c71ebb9` records a 1024-character limit on Pi skill descriptions.
- `skills-task-tool-coupling.sh` records that a Claude-only tool instruction in `.agro/skills/` breaks Codex and Pi.

Selected approach: run the council first, on the design of `/council` itself (US-001). Then author the accepted design through `/builder skill council` (US-002, US-003). Then add one probe and the trigger evidence (US-004). Then deliver the pull request (US-005).

## Storage

The skill writes no tracked file by default. The council record prints to the session. If the caller runs the council inside a task, the caller saves the record at `.agro/tasks/<slug>/council.md` and adds the record with `git add -f`. Trace output stays in `$TMPDIR/oh-prompt-miner/<UTC-date>/`, per the `/prompt-miner` privacy contract.

## Architectural Decisions

- **Source of truth:** `.agro/skills/council/SKILL.md` owns the procedure. `mine-traces.mjs` stays the only trace parser.
- **Role model:** The council is a skill that the active session runs. The advisor keeps the decision. The skill defines no project agent.
- **Independence:** Each perspective runs in a separate provider-native worker when the harness has one. Workers do not see other proposals before the first round ends.
- **Portability:** The skill names no Claude-only tool as a requirement. Without a subagent tool, the active session writes each perspective in sequence and marks the result `NOT-INDEPENDENT`.
- **Bounds:** The accepted design sets the perspective cap, the round cap, and the stop condition. This plan does not choose those values.
- **Privacy:** Council evidence cites trace aggregates only. The council never pastes, commits, or posts raw trace text.
- **Side effects:** The council writes no code, opens no pull request, and dispatches no implementation worker.

## Design Principles

- Code is the source of truth. Add no explanatory comments to tracked code. The probe carries only the machine-read header lines.
- Reuse before you add. Reuse `mine-traces.mjs`, `/builder`, and the existing provider symlinks.
- Keep one owner for each behavior. `/council` recommends. `/architect` decides structure. `/spec` builds. `/delegate` dispatches.
- Keep the council bounded. A council without caps turns into an open-ended token spend.
- Record what the council does not know. Each claim without evidence goes into the evidence limits.
- Apply `/ste` to every tracked prose file in this task.

## Out of Scope

- A change to `mine-traces.mjs` or to the `/prompt-miner` scoring model.
- A merge of the pull request.
- A migration of `/strategic-proposal` onto `/council`.
- A cron, a headless service, or a Herdr session for the council.
- A deterministic scorer for council votes. `/weigh` owns scoring.
