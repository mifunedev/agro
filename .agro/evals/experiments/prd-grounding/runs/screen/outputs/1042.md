# PRD: Separate the checkout bind from the home mount in sandbox install

Status: BLOCKED

Source: `work/issue-1042.md` (issue 1042).

## User Stories

### US-001: Select build mode from the checkout contents

**Description:** As an operator, I want build mode only for a `--repo <dir>` that holds `.devcontainer/Dockerfile` so that other host directories run the published image.

**Acceptance Criteria:**

- [ ] If `<repo>/.devcontainer/Dockerfile` exists and no seed sets `image.mode`, `seedConfig()` in `.agro/cli/src/commands/sandbox.ts` sets `image.mode` to `build`.
- [ ] If `<repo>/.devcontainer/Dockerfile` is absent and no seed sets `image.mode`, `seedConfig()` sets `image.mode` to `image`.
- [ ] For `--repo <empty dir>`, the saved `agro.json` holds `repo: <empty dir>` and `image: { mode: "image" }`.
- [ ] For `--repo <empty dir>`, the rendered compose env holds `AGRO_REPO_DIR=<empty dir>`.
- [ ] For `--repo <empty dir> --print-argv`, the printed argv holds `--no-build` and does not hold `--build`.
- [ ] For `--repo <empty dir>`, the rendered compose env holds `AGRO_SANDBOX_IMAGE=<image.ref or ghcr.io/mifunedev/agro:latest>`, so the build-capable base resolves the published image and not `sandbox-<name>`.
- [ ] For `--repo <checkout>` with `.devcontainer/Dockerfile`, the saved `agro.json` holds `image: { mode: "build" }`, and the entry selects the build-capable compose base.

### US-002: Refuse build mode without a Dockerfile before the wizard

**Description:** As an operator, I want install to refuse build mode without `.devcontainer/Dockerfile` so that the error names my flag and path, not a buildx `lstat` failure.

**Acceptance Criteria:**

- [ ] If the merged seed sets `image.mode: "build"` and `<repo>/.devcontainer/Dockerfile` is absent, `runSandboxInstall()` returns a non-zero code.
- [ ] The refusal message names `--repo`, the resolved repo path, and `.devcontainer/Dockerfile`.
- [ ] The refusal occurs before `runWizard()`: a test `io.ask` records zero questions.
- [ ] After the refusal, `<registry>/<name>/` does not exist.
- [ ] After the refusal, the test runner records no `bash` call to `docker-compose.sh`.

### US-003: Add the `--home-mount <dir>` install flag and wizard prompt

**Description:** As an operator, I want `agro sandbox install docker --home-mount <dir>` so that I choose the host path for `/home/sandbox` at create time, the only time the choice is safe.

**Acceptance Criteria:**

- [ ] `parseSandboxArgs()` in `.agro/cli/src/cli.ts` accepts `--home-mount <dir>` and returns an error for `--home-mount` without a value.
- [ ] `--home-mount <dir>` resolves `<dir>` to an absolute path and sets `storage.homePath` in the saved `agro.json`.
- [ ] `--home-mount <dir>` without `--repo` renders `AGRO_HOME_MOUNT=<dir>`, saves `image.mode: "image"`, and writes the image-only compose base to `.devcontainer/docker-compose.yml`.
- [ ] `--home-mount <dir>` with `--repo <checkout>` renders `AGRO_HOME_MOUNT=<dir>` and `AGRO_REPO_DIR=<checkout>`, and writes the build-capable compose base.
- [ ] The wizard asks one home-mount question after the Docker socket question. The default is blank, and a blank answer leaves `storage.homePath` unset.
- [ ] The wizard test in `.agro/cli/src/__tests__/sandbox.test.ts` asserts seven questions in order.
- [ ] If `--home-mount` is present, the wizard shows the flag value as the default for the home-mount question.

### US-004: Guard `config set storage.homePath` against an existing volume

**Description:** As an operator, I want `agro config set storage.homePath` to refuse for an existing sandbox volume so that a late change does not orphan my data.

**Acceptance Criteria:**

- [ ] If `docker volume inspect <name>_workspace` exits 0, `runConfigSet("storage.homePath", ...)` returns 1 and leaves `agro.json` unchanged.
- [ ] The refusal message names the volume `<name>_workspace`, states that the volume state becomes orphaned, and names `<override flag>`.
- [ ] With `<override flag>`, `runConfigSet("storage.homePath", ...)` returns 0 and writes the value.
- [ ] If `docker volume inspect <name>_workspace` exits non-zero, `runConfigSet("storage.homePath", ...)` returns 0 and writes the value.
- [ ] `<name>` resolves through `configuredContainerName()` and falls back to `DEFAULT_CONTAINER_NAME`, the same order `agro destroy` uses.
- [ ] `runConfigSet()` for any other field makes no `docker` call.

### US-005: Update the help text and the documentation

**Description:** As an operator, I want the help and docs to state what `--repo` and `--home-mount` bind so that I pick the right flag before the first `up`.

**Acceptance Criteria:**

- [ ] `printSandboxHelp()` in `.agro/cli/src/cli.ts` lists `--home-mount <dir>` in the usage line and the flag table.
- [ ] `printSandboxHelp()` states that `--repo` selects build mode only when `<dir>/.devcontainer/Dockerfile` exists.
- [ ] `docs/installation.md` and `docs/quickstart.md` state that `--repo` takes a host path and that build mode requires that path to be a harness checkout.
- [ ] `docs/configuration.md` documents `--home-mount` as the create-time door to `storage.homePath` and states the orphaned-volume hazard of a later `config set`.
- [ ] `docs/configuration.md` updates the `repo` row: the build-capable base follows `repo`, and build mode follows the checkout detection.

## Summary

Verified current state at commit `f94c1ad5`:

- `seedConfig()` at `.agro/cli/src/commands/sandbox.ts:125` sets `image.mode` to `build` whenever `repo` is set.
- The only `--repo` preflight is an existence check at `.agro/cli/src/commands/sandbox.ts:199`.
- `materialize()` at `.agro/cli/src/lib/registry.ts:95` selects the build-capable base (`composeRepo`) when `repo` is set, and the image-only base otherwise.
- The build-capable base `.devcontainer/docker-compose.yml:5` defaults the image to `sandbox-${SANDBOX_NAME}`. With `--no-build` and no `AGRO_SANDBOX_IMAGE`, that image does not exist. A mode fix alone therefore does not start the empty-directory case. US-001 renders the published image ref for that case.
- `runSandbox()` at `.agro/cli/src/commands/lifecycle.ts:163-169` sets `AGRO_SANDBOX_IMAGE` only when `image` or `imageRef` is passed.
- `.devcontainer/entrypoint.sh:160-196` seeds the control plane into an empty `/home/sandbox/harness` bind.
- `storage.homePath` renders as `AGRO_HOME_MOUNT` at `.agro/cli/src/lib/config-render.ts:40`. No install flag and no wizard question set the field.
- `runConfigSet()` in `.agro/cli/src/commands/config.ts` writes any known field with no Docker check.
- Compose names the home volume `<SANDBOX_NAME>_workspace`, because each base sets `name: ${SANDBOX_NAME:-agro}` and declares the volume `workspace`.
- The existing test at `.agro/cli/src/__tests__/sandbox.test.ts:148` uses an empty `mkdtemp` directory and expects `image: { mode: "build" }`. US-001 changes that result. See Open Question 3.

Selected approach:

1. Add one function, `isHarnessCheckout(repo)`, that returns `existsSync(join(repo, ".devcontainer", "Dockerfile"))`. `seedConfig()` uses it as the build-mode default.
2. Run the build-mode preflight in `runSandboxInstall()` after `seedConfig()` and before `runWizard()`. `mkdirSync(root)` runs later, so an early return leaves no entry.
3. If `repo` is not a checkout and `image.ref` is unset, write the resolved published image ref to `config.image.ref`. Later lifecycle verbs read `image.ref` from `agro.json` and render the same `AGRO_SANDBOX_IMAGE`.
4. Add `homeMount` to `SandboxInstallOptions` and `SANDBOX_VALUE_FLAGS`. The flag sets `config.storage.homePath` before the wizard, so the wizard shows the value as the default.
5. Add the volume check to `runConfigSet()` for the key `storage.homePath` only.

## Storage

The change adds no new persistence. The flags write existing `agro.json` fields in the registry entry `~/.agro/sandboxes/<name>/agro.json`: `repo`, `storage.homePath`, `image.mode`, and `image.ref`. Follow the existing `writeOhConfig()` path. The CLI reads the Docker named volume `<name>_workspace` through `docker volume inspect` and never writes the volume.

## Architectural Decisions

- **Source of truth for build mode:** the presence of `<repo>/.devcontainer/Dockerfile`, unless a seed `agro.json` sets `image.mode`. A seed value wins, and the preflight validates the value.
- **Source of truth for the compose base:** `repo`, as today. `--home-mount` does not change the base selection.
- **Source of truth for the volume name:** the Compose project name, resolved by `configuredContainerName()` with the `DEFAULT_CONTAINER_NAME` fallback.
- **Execution location:** all changes run on the host inside the CLI. The container and `.devcontainer/entrypoint.sh` do not change.
- **Scope of the guard:** the guard covers `config set storage.homePath` only. The guard covers both the project root and `--sandbox <name>`.
- **Lifecycle door:** `agro` stays the only door. The legacy `oh` alias gets the same flags through the shared parser.

## Design Principles

- Keep all application changes in `.agro/cli/`. Do not add explanatory comments to tracked code.
- Fail before side effects: validate the build assumption before the wizard, before `mkdirSync()`, and before Docker.
- Name the flag, the path, and the missing file in each refusal.
- Reuse `configuredContainerName()`, `configuredImage()`, and `DEFAULT_SANDBOX_IMAGE`. Do not add a second resolution path.
- Keep the change small. Do not rename `--repo`. Do not touch the compose files or the entrypoint.

## Open Questions

1. **Override flag name.** The issue requires an explicit override flag for `config set storage.homePath` and does not name the flag. The plan uses `<override flag>`. Recommendation: `--force`, which `agro update` already uses for a gate override. This question blocks US-004.
2. **"Explicit flag" for build mode.** The issue says build mode comes "from an `agro.json` seed or an explicit flag". No install flag sets `image.mode: build` today. The plan applies the preflight to the seed only and adds no flag. Confirm.
3. **Existing test at `sandbox.test.ts:148`.** The issue says the case stays green. The case uses an empty directory and expects `build`, which contradicts Part 1. The plan adds `.devcontainer/Dockerfile` to that fixture and keeps every other assertion. Confirm.
4. **Entry seed from a failed install.** A registry entry that an earlier release wrote for an empty directory carries `image.mode: "build"`. A re-install then hits the US-002 refusal. Choose one: A. refuse and name `agro destroy <name>` or `agro config set --sandbox <name> image.mode image` in the message; B. apply the preflight to the `--repo` seed only and re-infer the mode for an entry seed. The plan assumes A.
5. **Docker unavailable during `config set`.** If `docker volume inspect` cannot run, the guard cannot see the volume. Choose one: A. write the value and print a warning; B. refuse unless `<override flag>` is present. The plan assumes A, which matches the non-zero-exit criterion in US-004.
6. **Public docs owner.** Decide whether this task or a follow-up issue updates `mifunedev/agro-web`.
