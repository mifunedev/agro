# PRD: Retire pi-dynamic-workflows from Pi defaults

Status: DRAFT

## User Stories

### US-001: Remove the dynamic workflow pin from the default Pi packages

**Description:** As an operator, I want the harness Pi defaults to exclude `pi-dynamic-workflows` so that `/delegate` stays the only bounded delegation path in a fresh Pi session.

**Acceptance Criteria:**

- [ ] `.pi/settings.json` has no `packages` entry that contains the substring `pi-dynamic-workflows`.
- [ ] `.pi/settings.json` keeps the other nine `packages` entries in the current order, byte for byte.
- [ ] Every other key and value in `.pi/settings.json` stays unchanged. `git diff .pi/settings.json` shows only the removed entry and the comma on the previous line.
- [ ] `.pi/extensions/__tests__/settings.test.ts` asserts the new exact nine-entry list with `toEqual`.
- [ ] `.pi/extensions/__tests__/settings.test.ts` asserts that no `packages` entry matches the case-insensitive pattern `pi-dynamic-workflows`. The pattern covers the `git:`, `npm:`, and URL sources, not only the old commit string.
- [ ] The implementation owner adds both assertions first. `pnpm exec vitest run .pi/extensions/__tests__/settings.test.ts` exits 1 before the settings edit and exits 0 after the settings edit.

### US-002: Retire the tool from current documentation

**Description:** As a Pi user, I want current documentation to point me to `/delegate` instead of the Pi `workflow` tool. I also want to know how an old install still reaches my session.

## Architectural Decisions

- `.pi/settings.json` stays the single source of truth for harness Pi defaults.
- Retirement means removal from defaults. The harness does not detect, block, or purge an operator-managed global or `-e` install.
- `/delegate` owns bounded delegation. The plan adds no replacement workflow engine.
- The negative assertion matches the package name, not the commit string. A pin to a new commit, an `npm:` source, or a URL source fails the test.
- No ADR is required. The change removes one default package and adds no abstraction.

Affected surfaces:

- Host and sandbox: applied. Edits and tests run in the sandbox worktree. The host needs no change.
- Lifecycle door: not applicable. No `agro` verb reads `.pi/settings.json` packages.
- Canonical and provider surfaces: not applicable. `.pi/settings.json` is Pi's own project configuration, not a `.agro/` mirror. No symlink changes.
- Root and scaffold: applied. The root checkout and the `/opt/agro-seed/` image seed both carry `.pi/settings.json`.
- Interactive and headless processes: applied. A running Pi session in Herdr keeps the tool until restart. The Slack gateway loads `pi-messenger-bridge` by `--extension` and needs no restart for this change.
- Local and remote operation: applied. The change is a tracked file edit and holds on a remote VM.
- Parallel operation: applied. One implementation owner edits one isolated worktree.
- Public documentation: applied. US-003 records the `mifunedev/agro-web` disposition.
- Verification: applied. See the test plan.

## Design Principles

- Code is the source of truth. The test pins the exact list and the absence of the package.
- Delete obsolete paths. Delete the integration page instead of marking it deprecated.
- Keep the smallest change. Do not edit unrelated packages, Pi upstream, or user files.
- Keep history intact. Do not rewrite the `CHANGELOG.md:681` entry or archived task files.

## Out of Scope

- Changes to Pi upstream or to the `pi-dynamic-workflows` repository.
- Removal of global Pi installs, Pi package caches, or `-e` usage.
- Migration of user workflow scripts.
- A replacement workflow engine.
- Changes to `@tintinweb/pi-subagents`, `@tintinweb/pi-tasks`, or any other orchestration tool.
- Edits in `mifunedev/agro-web`. US-003 records the disposition only.
- A rebuild or republish of published images.
