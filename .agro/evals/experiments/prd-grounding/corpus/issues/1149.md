## Description

The Bash secret-exposure guard denies benign commands that only mention a trigger word:

- Any command whose text contains the word `history` is denied as a shell-history read, including a `git commit -m` message such as "apply task-history signal".
- A `jq '.env // {}' .claude/settings.json` filter is denied as a secret-file read. `.claude/settings.json` holds no secret.

Both hit during #1147 (PR #1148). The workaround was rewording commit messages; a worker also restored a file through `git show HEAD:<file> >` after a related guard denied `git checkout --`.

## Expected

- Match shell-history access (`history`, `~/.zsh_history`, `~/.bash_history`, `fc -l`), not the bare word inside quoted arguments.
- Match `.env` file paths, not a `jq` filter key named `env`.

## Acceptance Criteria

- [ ] `git commit -m "record history of X"` is allowed; `cat ~/.zsh_history` is still denied
- [ ] `jq '.env' .claude/settings.json` is allowed; `cat .env` is still denied
- [ ] Existing hook tests pass
