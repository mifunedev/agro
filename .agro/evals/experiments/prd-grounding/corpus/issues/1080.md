## Symptom

In a sandbox whose checkout is an `.agro/` generation workspace, `agro gateway <name>` fails with:

```
missing lifecycle script /home/sandbox/harness/.oh/scripts/gateway.sh
```

## Cause

Two distinct layers, which must not be conflated:

**Old installed bundle (the reported failure).** `/usr/local/bin/agro` → `/opt/oh/dist/agro.js`, which is `@mifune/agro` **v0.9.0** — an image-time copy of `.agro/cli/` from a build that predates the `.agro`/`.oh` generation pair. That bundle hardcodes `<root>/.oh/scripts/...`, so it resolves a path this checkout does not have. Current source is v0.12.2.

**Current source (the real, still-live defect).** `requireLifecycleScript` resolves the control dir correctly through `resolveProjectLayout` (`.agro/cli/src/lib/execution/runner.ts:70-79`), so the path bug itself is already fixed. But its error message tells the operator to:

> run \`agro update\` to re-vendor it

That advice is wrong on two counts:

1. `agro update` is **CLI self-upgrade**, not payload vendoring. Vendoring the control plane is `oh update` (`.agro/cli/src/cli.ts:104-115`, `:182-226`).
2. For an **image** installation — `/opt/oh/`, which is exactly how the CLI is installed in every AGRO sandbox — `agro update` *refuses*: `classifyInstallation` returns `{ kind: "image" }` for any `/opt/oh/` prefix and `refuseUnsupported` errors with "the sandbox image ships this CLI; pull a newer image on the host" (`.agro/cli/src/commands/self-upgrade.ts:70`, `:117`, `:185-191`).

So an operator who hits this error and follows the message reaches a dead end — the single most likely audience for the message is the one it cannot help.

## Proposed correction

Smallest supported change, no ownership or lifecycle change:

- Make the `requireLifecycleScript` diagnostic **installation-aware**: for an image install, point at the host image refresh; for npm/standalone/source installs, name the verb that actually re-vendors the payload.
- Name the **generation mismatch** when the other generation's control dir is the one that exists on disk, so version skew is diagnosed rather than guessed at.
- Regression coverage that fails against the current message and passes after.
- Operator-facing recovery documentation for a sandbox already in this state.

Explicitly **not** proposed: a `.oh` → `.agro` symlink, automatic boot-time installation or refresh of `/opt/oh` (an ownership change requiring architecture review and operator approval), any change to Slack credentials, or any mutation of `/opt/oh` on a running sandbox.
