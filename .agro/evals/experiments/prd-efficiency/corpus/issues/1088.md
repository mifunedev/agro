## Summary

Retire `.agro/tasks/<slug>/evidence.md` in favour of the PR description, and close two gaps this session exposed in the workflow's own gates.

## Problem

Three findings from the `agro-workspace-verb` build (#1086), each now a `kind: pattern` page:

1. **The evidence artifact is in the wrong place.** `evidence.md` lives in a gitignored folder, needs `git add -f` to reach the diff, and `execute.md` itself warns that one added without `-f` is "present on disk and absent from the PR diff — which is the same as not having it". The reviewer is already in the PR description. Moving it there gives a versioned history in GitHub, removes a class of silent omission, and removes the `git ls-files --error-unmatch` half of the evidence gate.

2. **A completed task folder is never checked against the artifacts the procedure requires.** The #1086 build skipped `/audit implementation`, produced no simplicity review, and never ran `knowledge-impact.sh`. Nothing failed. `simplicity-review.json` and `simplify-rounds.json` were simply absent, and absence is not an oracle.
   → `pattern-spec-procedure-executed-from-summary`

3. **A gate that cannot run reads as a gate that failed.** `pr-acquire.sh:32` requests `closingIssuesReferences`; no `gh` before 2.101.0 supports it, so `/audit implementation` gate 3 and the whole `/audit pr` route were unrunnable on the operator's host. The driver printed `gate3: FAIL (classification exited 1)` — failing closed, correctly — but nothing distinguished a tooling gap from a real PR defect.
   → `pattern-audit-gate-unrunnable-reads-as-defect`

## Scope

- Move the five evidence questions into the PR-body contract; drop the file across 4 probes and 12 skill/doc files.
- Add a probe asserting a completed task folder carries every artifact `execute.md` requires.
- Give the audit driver a distinct tooling-blocked signal, separate from `FAIL`.
