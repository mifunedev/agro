`claude update` and `codex update` fail inside the sandbox:

```
Warning: Can't auto-update: npm global folder isn't writable
Error: Insufficient permissions to install update
```

```
npm error code EACCES
npm error path /usr/local/lib/node_modules/@openai
Error: `npm install -g @openai/codex` failed with status exit status: 243
```

`agro harness install` lands each harness in `$NPM_USER_PREFIX` (`/home/sandbox/.local`) with an explicit `npm --prefix`, but npm's own global prefix in the sandbox is still `/usr/local`, which the `sandbox` user cannot write. A harness that self-updates calls a bare `npm install -g` and hits `/usr/local`. `sudo claude update` cannot work either: sudo's secure_path excludes `~/.local/bin`, so the binary is not found, and a root-owned install would land outside the home volume and vanish on recreate.

Expected: npm's global prefix for the sandbox user is the same home-volume prefix the harness door installs into, so a harness updates itself without sudo and the update persists across a container recreate.
