`agro sandbox install docker` conflates two different mounts. This issue covers
both halves, because both live in `runSandboxInstall` and share one test surface.

## Symptom

```
agro sandbox install docker --repo ~/sandboxes/agro-sbx-1 --name agro-sbx-1
...
[+] up 0/1
 ⠙ Image sandbox-agro-sbx-1 Building
resolve : lstat /home/ryaneggz/sandboxes/agro-sbx-1/.devcontainer: no such file or directory
```

The operator passed an empty host directory to `--repo`. The intent was to make
the sandbox **persist** at that host path, so host tools can read the files. The
command failed inside `docker buildx` after the wizard completed.

## Two mounts, one flag

The compose files define two bind-capable mounts:

| Mount | Compose | Env key | Config field | Purpose |
|---|---|---|---|---|
| `/home/sandbox` | `docker-compose.yml:12`, `docker-compose.image-only.yml:9` | `AGRO_HOME_MOUNT` | `storage.homePath` | Where the sandbox persists |
| `/home/sandbox/harness` | `docker-compose.yml:13` | `AGRO_REPO_DIR` | `repo` | Binds an existing checkout |

`--repo` is the only install flag that reaches either one. It drives the second
mount. The operator wanted the first. No install flag reaches the first mount at
all.

## Part 1 — `--repo` forces build mode

`AGRO_REPO_DIR` carries two meanings that the CLI never separates:

1. **Bind-mount source** (`.devcontainer/docker-compose.yml:13`).
2. **Docker build context** (`.devcontainer/docker-compose.yml:9-10`, with
   `dockerfile: .devcontainer/Dockerfile`).

`seedConfig()` sets `image.mode` to `build` whenever `--repo` is present
(`.agro/cli/src/commands/sandbox.ts:118-121`):

```ts
config.image = {
  ...config.image,
  mode: seed?.image?.mode ?? (config.repo === undefined ? "image" : "build"),
};
```

Any `--repo` value therefore asserts "this directory is an Open Harness checkout
that contains `.devcontainer/Dockerfile`". The only preflight is an existence
check (`.agro/cli/src/commands/sandbox.ts:196-201`). Directory *contents* are
never validated. An empty directory passes the wizard, writes a registry entry,
and fails minutes later with a buildx `lstat` error that names neither the flag
nor the assumption that broke.

The plumbing already supports "bind an arbitrary host path and run the published
image". `.devcontainer/entrypoint.sh:159-166` branches on whether
`/home/sandbox/harness` is a mountpoint **holding a control directory**, not on
whether it is a bind. An empty bind falls through to
`.devcontainer/entrypoint.sh:193-196`, which seeds the control plane into the
bound host directory. Only the `mode` inference blocks the operator's command.

### Fix

1. Key build mode off `existsSync(<repo>/.devcontainer/Dockerfile)`, not off the
   presence of the flag.
2. When the path exists but is not a checkout, keep the bind and leave
   `image.mode` at `image`.
3. When `image.mode` is `build` (from an `agro.json` seed or an explicit flag)
   and `<repo>/.devcontainer/Dockerfile` is absent, exit non-zero **before** the
   wizard. Name the flag, the path, and the missing file.
4. Leave no registry entry behind when install fails preflight.

## Part 2 — add `--home-mount <dir>`

`storage.homePath` already binds `/home/sandbox` to a host path
(`.agro/cli/src/lib/config-render.ts:40`, documented at
`docs/configuration.md:88`). It has no install flag and no wizard prompt. It is
reachable only through `agro config set storage.homePath <dir> [--sandbox <name>]`.

`config set` is the wrong door, because `storage.homePath` is a **create-time**
decision:

- Set before the first `up`: `/home/sandbox` binds to the host path, the
  entrypoint seeds it, and the sandbox works.
- Set after the sandbox has booted: the next `up` swaps the mount source. The
  named volume `<name>_workspace` keeps all existing state, orphaned and
  invisible. The container boots against an empty host directory and re-seeds
  from the image. The change is silent and presents as data loss.

An install flag puts the decision at the only moment it is safe to make.

### Fix

1. Add `--home-mount <dir>` to `agro sandbox install`. It sets
   `storage.homePath`. The name matches the existing `AGRO_HOME_MOUNT` env key
   and the `/home/sandbox` target.
2. Add a wizard prompt for it, defaulting to unset (the named volume).
3. Guard `agro config set storage.homePath`. Refuse when the sandbox's named
   volume already exists, unless the operator passes an explicit override flag.
   State that existing state in the volume will be orphaned.
4. `--home-mount` alone must not select the build-capable compose base.
   `materialize()` picks the base from `repo` (`.agro/cli/src/lib/registry.ts:95`),
   so the image-only base is correct and already carries the home-mount line
   (`.devcontainer/docker-compose.image-only.yml:9`).

## Known edge, not in scope

UID and GID reconciliation runs only in the checkout-detected branch
(`.devcontainer/entrypoint.sh:167-191`). The empty-bind path reaches
`chown -R` to the container's `sandbox` UID. On a host whose UID is not 1000,
host-side files end up owned by the wrong user. Track separately.

## Impact

- The natural "persist this sandbox at this host path" request fails on first run.
- Docker emits the error, not `agro`, so it points at `.devcontainer/` instead of
  at the flag that caused it.
- A registry entry is left behind after the failure.

## Verification

- `--repo <empty dir>` resolves to `image.mode: "image"`, renders
  `AGRO_REPO_DIR`, and `--print-argv` shows no `--build`.
- `image.mode: "build"` with a repo lacking `.devcontainer/Dockerfile` exits
  non-zero with the guidance message and creates no registry entry.
- `--home-mount <dir>` renders `AGRO_HOME_MOUNT=<dir>`, keeps
  `image.mode: "image"`, and selects the image-only compose base.
- `--home-mount` with `--repo <checkout>` renders both keys and selects the
  build base.
- `config set storage.homePath` refuses when the named volume exists, and
  proceeds with the override flag.
- Existing `--repo` build-mode coverage
  (`.agro/cli/src/__tests__/sandbox.test.ts:148`) stays green.
- Compose-string probes stay green: `.agro/evals/probes/oh-devcontainer-restructure.sh:46`,
  `.agro/evals/probes/oh-home-mount.sh:48`, `.agro/evals/probes/oh-image-only-deploy.sh:147`.

## Docs

- `docs/installation.md:97-114`, `docs/quickstart.md:88-111`: state that `--repo`
  is a host path, and that build mode is selected only when that path is itself a
  harness checkout.
- `docs/configuration.md:88`: document `--home-mount` as the create-time door to
  `storage.homePath`, and the orphaned-volume hazard of setting it later.
- `.agro/cli/src/cli.ts:255-271`: update install help text.

## Follow-up

The flag rename (`--repo` -> `--checkout`) is tracked separately. It is a wide,
mechanical compatibility edit and does not belong in this behavior fix.
