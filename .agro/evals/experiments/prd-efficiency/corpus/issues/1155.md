## Description

The Bash secret guard `.agro/hooks/deny-env-dump.sh` has two remaining accuracy gaps. The advisor found both during #1150 (PR #1154).

1. **False allow: interpreter environment dumps.** The guard allows a script interpreter that prints the process environment:
   - `python3 -c 'import os; print(dict(os.environ))'`
   - `perl -e 'print "$_=$ENV{$_}\n" for keys %ENV'`

   `node -e 'console.log(process.env)'` is denied, but only through an unrelated term.
2. **False deny: `.env` inside a search pattern.** The secret-path check reads `.env` in a search pattern as a secret-file path:
   - `grep process.env src/index.ts`
   - `grep "Config.Env" <file>`

   The same check denies command text that only names a guarded command, for example notes passed to `jq --arg`.

## Steps to Reproduce

1. Put one command from the lists above in a file.
2. Feed it to the hook: `jq -nc --rawfile c <file> '{tool_input:{command:($c|rtrimstr("\n"))}}' | bash .agro/hooks/deny-env-dump.sh`.
3. Observe empty output (`allow`) for the list 1 commands and a `deny` decision for the list 2 commands.

## Expected Behavior

- The guard denies an interpreter command that reads the whole process environment.
- The guard allows a search pattern that contains `.env` when no argument names an env file.

## Actual Behavior

The guard allows the list 1 commands and denies the list 2 commands.
