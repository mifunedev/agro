## User Stories

- As an **operator**, I want the default image tag to equal my `agro` CLI version so that each sandbox runs a known release, not `latest`.
- As an **operator**, I want to type `agro sandbox install docker --version=0.13.0` so that I can pin an official release without typing the full image ref.
- As an **operator**, I want an install-time pin to persist so that `agro start` and `agro restart` keep the same release.
- As an **operator**, I want the docs to show `--version` as the way to pin a release so that I skip the full image ref.

---

## Summary

Today the operator pins a release with `--image=ghcr.io/mifunedev/agro:<X.Y.Z>`, and the default is `ghcr.io/mifunedev/agro:latest`. This change adds `--version <X.Y.Z>` for the official image and keeps `--image=<ref>` for custom images. The CLI rejects `--version` together with `--image=<ref>`. The default tag becomes the CLI version. If the CLI version is not a plain `X.Y.Z` release, the default ref uses `latest`. The install stores only an explicit pin in `image.ref`.

Plan: `.agro/tasks/sandbox-install-version/prd.md`.
