Drop CI steps and path filters that prove nothing, and stop rebuilding the sandbox image on every `.agro/**` change.

## Why
Session review of the PR pipelines: `pnpm run lint` and `pnpm run format:check` always echo success. Path filters name deleted trees (`packages/**`, `.oh/**`, `oh.json`). Boot-guard's `.agro/**` glob rebuilds the image for skill/probe/docs-adjacent control-plane edits.

## Do
- Remove the no-op Lint and Format check steps from `ci-harness.yml` and `release.yml`.
- Remove dead path filters that name no file (`packages/**`, `packages/oh/**`, `.oh/**`, `oh.json`, `.oh/scripts/*`, `.oh/cli/**`).
- Remove redundant globs already covered by `.agro/**` in harness CI (skills/hooks/evals/knowledge), and update probes that pin those literals so `.agro/**` counts as covering knowledge.
- Narrow boot-guard paths to image/boot inputs (`.devcontainer/**`, `.agro/cli/**`, `.agro/scripts/**`, `.agro/install/**`, compose/smoke/verifier scripts as covered by scripts, `agro.json`, `.example.env`, `.dockerignore`, the workflow file). Do not trigger on the whole control plane.

- Align `/ci-status` and the feat issue template with the real gates.

- Drop eval probes, typecheck, tests, boot smoke, upgrade smoke, or optional-harness-install.
