## Symptom

A fresh `agro sandbox install docker` ends with:

```
next: oh shell <name>
```

The operator invoked `agro`. The success message names `oh`, the legacy binary.

## Diagnosis

The product abstraction exists and is correct. `.agro/cli/src/lib/product.ts:38`
resolves the active product from the invoked name:

```ts
return invokedName(argv1) === LEGACY_PRODUCT.bin ? LEGACY_PRODUCT : AGRO_PRODUCT;
```

`AGRO_PRODUCT.bin` is `agro` (`product.ts:16`), `LEGACY_PRODUCT.bin` is `oh`
(`product.ts:24`). `cli.ts` threads the resolved `bin` through every help string.

Runtime command output does not. The command layer hardcodes the literal `oh`,
at **33 operator-facing sites** across five files:

| File | Examples |
|---|---|
| `.agro/cli/src/commands/sandbox.ts` | `:212`, `:217`, `:223`, `:232`, `:246`, `:257`, `:274`, `:319` |
| `.agro/cli/src/commands/lifecycle.ts` | `:194`, `:242`, `:248`, `:331`, `:338`, `:364` |
| `.agro/cli/src/commands/tool.ts` | `:148`, `:175`, `:234`, `:254-255`, `:279` |
| `.agro/cli/src/commands/harness.ts` | `:127`, `:144`, `:185`, `:221-222`, `:255`, `:261` |
| `.agro/cli/src/commands/update.ts` | `:79`, `:91`, `:94` |

So #942 migrated help text to the product abstraction and left runtime messages
behind.

The worst instance is `.agro/cli/src/commands/sandbox.ts:319`:

```ts
if (code === 0) io.stdout(`next: oh shell ${config.name}\n`);
```

That is the final line of a successful first install — the most-read string in
the product — and it points a new operator at the deprecated binary.

Several messages also instruct recovery with the wrong command: `oh sandbox`
(`tool.ts:148`, `harness.ts:127`), `oh sandbox install docker`
(`lifecycle.ts:248`), and `oh secret set` (`config.ts`).

## Impact

Not broken. `oh` remains a working alias through the SLA, so every printed
command still runs. The defect is that the CLI teaches the deprecated name at
the exact moments an operator is most likely to copy a command: first install,
and every error recovery hint.

## Proposed remediation

Thread the resolved `bin` into the command layer, the way `cli.ts` already does.

1. Pass the active `Product` (or its `bin`) into each command's options or its
   IO object. `runSandboxInstall`, `runSandbox`, `runTool*`, `runHarness*`, and
   `runUpdate` all already take an options bag.
2. Replace each hardcoded `oh` with the threaded value.
3. **Do not find-and-replace `oh` with `agro`.** That would break the legacy
   path: an operator who invokes `oh` must keep being told `oh`. The whole point
   of `productFromArgv` is that the message matches the invocation.
4. Add a test asserting both directions: invoking as `agro` prints `agro` in the
   install success line and in at least one error path; invoking as `oh` prints
   `oh`.

## Verification

- `agro sandbox install docker …` ends with `next: agro shell <name>`.
- The same install invoked as `oh` ends with `next: oh shell <name>`.
- No tracked file under `.agro/cli/src/commands/` contains a hardcoded operator-
  facing `oh ` literal. A probe can assert this cheaply with `git grep`.
- `/eval` reports no regression.
