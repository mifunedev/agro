Apply Balena-style Docker cache hygiene to `.devcontainer/Dockerfile`: do not copy the whole repo before the Python kernel, and clean installer leftovers in the same RUN that creates them.

## Why
https://docs.balena.io/learn/deploy/build-optimization — `COPY` checksums invalidate every later layer. The `home` stage copies `.` into `/opt/agro-seed` and then runs `provision-python.sh`, so any context change rebuilds the kernel. The `final` stage must still `COPY .` last (that is the seed).

## Do
- In the `home` stage, copy only `provision-python.sh` (and what it needs) before the kernel RUN. Leave `COPY .` as the last content instruction of `final`.
- In the CLI and global npm install RUNs, clean `npm` cache and `/tmp` in the same layer. Remove leftover uv installer files under `/root/.local` after copying binaries to `/usr/local/bin`.
- Keep `--no-install-recommends` and apt-list cleanup. Do not merge the split apt layers (gh vs docker vs base). Do not strip sandbox tools.

## Do not
- Change boot-guard path filters (separate issue).
- Rename `OH_*` in this change.
