## Context

Claude Code 2.1.277 (2026-09-18) added native `AGENTS.md` support:

> Added AGENTS.md support: in a project with no CLAUDE.md, Claude Code reads AGENTS.md instead; change it under "Project instructions" in `/config` (not yet on Bedrock, Vertex or Foundry)

Under the default `claude-md-or-agents-md` setting, Claude reads:

- every root/ancestor `AGENTS.md` and `.claude/AGENTS.md` at session start, and
- a subdirectory's `AGENTS.md` when it opens a file there with the Read tool.

That is exactly the behavior the five tracked `CLAUDE.md -> AGENTS.md` symlinks emulate:

```
CLAUDE.md               -> AGENTS.md
.worktrees/CLAUDE.md    -> AGENTS.md
projects/CLAUDE.md      -> AGENTS.md
crons/CLAUDE.md         -> AGENTS.md
.agro/logs/CLAUDE.md    -> AGENTS.md
```

## The sharper point

The symlinks are not merely redundant. Per the memory docs, a `CLAUDE.md` in the working directory **or any directory above it** disables the `AGENTS.md` path. Shipping them is therefore what *suppresses* the native behavior on every supported provider.

This matters for non-negotiable 2 (coding-harness choice does not change the workspace): Codex and Pi already read `AGENTS.md` natively. Retiring the alias makes `AGENTS.md` the single source of truth for every harness, rather than one canonical file plus a per-provider mirror the repo must maintain and probe.

## Cost, stated plainly

Retiring the symlinks raises AGRO's floor to Claude Code >= 2.1.277, and drops project instructions for sessions that cannot read `AGENTS.md` at all: Amazon Bedrock, Vertex, Foundry, and sessions with telemetry disabled.

That is a real compatibility decision for a shipped product, and it is the maintainer's call rather than the implementer's. The escape hatch for an affected operator is a root `CLAUDE.md` containing `@AGENTS.md` (plus a per-directory one for each nested guide they need), or simply restoring the symlinks in their own checkout.

## Proposed change

- Delete the five symlinks.
- Drop their `.gitignore` and `.dockerignore` negations and the `ci-harness.yml` path-filter entries.
- Replace the "provider-compatibility symlink" notice in each `AGENTS.md`.
- Update `docs/glossary.md`, `.agro/scripts/README.md`, and the four skill references that name `CLAUDE.md` as this repo's bootloader. Leave generic "read the target repo's `AGENTS.md`/`CLAUDE.md` if present" guidance alone, since it applies to arbitrary repos.
- Invert the three probes that assert the symlink exists, and add one probe guarding the new invariant.
- Document the version floor and the escape hatch.
